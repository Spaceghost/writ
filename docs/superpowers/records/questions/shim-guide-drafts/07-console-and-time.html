Shim review 7 of 9: Genode.log, Genode.now, Genode.sleep

These three C functions are what the Bend effects Genode.log, Genode.now, and Genode.sleep call (their C twins live in hosts/genode/effects/). Logging uses the component's existing LOG session. Time uses one Timer::Connection, a session to the timer service, opened on first use with the label writ_shim and kept for the component's life. Before opening it, the shim probes the route with Env::try_session, because a plain session request that the parent denies leaves the component hanging silently (header 1185-1190). The claim to check: the Bend program alone decides what is logged and when to wait (1146-1148), and the shim stops the component only when the clock itself cannot be trusted. INVENTORY.md:233-259 ("Timer failure outcomes") and the Timer bullet at :149-161 list this.

Open: writ_mem.cc:1140-1287

Claim 2

writ_shim_sleep_ms returns only once the session clock has advanced by at least ms, and otherwise ends the component with exit 1 on a backwards clock, a clock that did not advance, or the round cap.

1265	extern "C" void writ_shim_sleep_ms(uint32_t ms)
1266	{
1267	    Timer::Connection *t = _timer_session();
1268	    if (!t || ms == 0) return;
1269	    uint64_t const start    = t->elapsed_ms();
1270	    uint64_t const deadline = start + ms;
1271	    uint64_t       last     = start;
1272	    for (unsigned round = 0;; round++) {
1273	        uint64_t const now = t->elapsed_ms();
1274	        if (now >= deadline) return;
1275	        if (now < start)
1276	            _timer_fail("Timer clock went backwards during a sleep");
1277	        if (round > 0) {
1278	            if (now <= last)
1279	                _timer_fail("Timer clock did not advance across msleep");
1280	            _timer_short_wakes++;  /* msleep returned before the deadline */
1281	        }
1282	        if (round == MAX_SLEEP_ROUNDS)
1283	            _timer_fail("sleep exceeded MAX_SLEEP_ROUNDS msleep calls");
1284	        last = now;
1285	        t->msleep(deadline - now);
1286	    }
1287	}
1210	/* Ends the component with exit value 1 after one line; does not return. */
1211	[[noreturn]] static void _timer_fail(char const *what)
1212	{
1213	    error("writ_shim: ", what, ", component exits 1");
1214	    _env->parent().exit(1);
1215	    sleep_forever();
1216	}

What I see. The loop is as described. The three stops are fail-stop host-failure handling: they read only the timer's own readings and a round counter. MAX_SLEEP_ROUNDS (16) is a bounded mechanical limit that keeps a broken connection from spinning. The only Writ-visible effect is availability: a bad clock stops every client of the component.

Recommendation: Confirmed, the deadline loop and the three stops are all here.
