# Plan: Nix flake for deterministic builds

Purpose: `nix develop` gives every contributor and every agent the exact pinned toolchain (Bend 2.0.39, a clang new enough for native builds, QEMU, Node, Bun, OpenSpec 1.16.0, Python), and `nix build` produces Writ's native test binary and runs its checks reproducibly, so "it passed on my machine" means the same thing on every machine. Read `docs/INSTALL.md` and `VERIFICATION.md` first: they state the pinned versions, the release checksum, and the commands whose outputs are recorded.

## Global Constraints

- Nix is installed for the current user (`nix --version` works) with flakes enabled; if flakes are not enabled, use `--extra-experimental-features 'nix-command flakes'` on every command and say so in the README section you write.
- Files: `flake.nix` and `flake.lock` at the repository root, plus a `nix/` directory for any helper expressions. Commit the lock file. Do not modify any `.bend` file. Do not modify `.gitignore` except to add Nix result symlinks (`/result*`).
- Pin `nixpkgs` to a specific commit (record it in the lock) on the `nixos-unstable` branch as of the day you run `nix flake lock`.
- Bend: package the official Linux x86_64 release tarball `https://github.com/bendlang/bend/releases/download/v2.0.39/bend-2.0.39-linux-x64.tar.gz` with the SHA-256 recorded in `docs/INSTALL.md` (convert to the SRI form Nix expects). The release contains prebuilt dynamically linked binaries; use `autoPatchelfHook` (and `stdenv.cc.cc.lib` or whatever libraries `patchelf` reports missing) so `bend version` runs from the store. Keep the extracted `bin/`, `bend2/`, and `guide/` directories together as the install guide requires. Set `BEND_NO_TELEMETRY=1` in the wrapper or the shell hook. Do not fetch Bend from any other source or build it from source.
- OpenSpec 1.16.0: package `@fission-ai/openspec` at exactly 1.16.0 with `buildNpmPackage` (generate the `package-lock.json` under `nix/openspec/` and commit it, with the `npmDepsHash` recorded) so `openspec --version` in the shell prints `1.16.0`. If `buildNpmPackage` proves impossible within an hour, fall back to a wrapper script that runs `bunx @fission-ai/openspec@1.16.0` and state in the README that the fallback is not hermetic.
- Determinism evidence: build `packages.tests-native` twice from a clean state (`nix build --rebuild` or two separate `nix build` invocations after `nix store delete` of the output) and record both output store paths and their `nix hash path` values in `verification/nix-determinism.txt`; they must match. If they do not, record the diff of the two outputs and report DONE_WITH_CONCERNS.
- Everything the flake builds must work offline inside the Nix sandbox: no network access during `nix build` beyond fixed-output fetches with hashes.
- Do not push. Commit on the current branch only.

### Task 1: The Bend package and the dev shell

Write `flake.nix` with:

- `packages.x86_64-linux.bend`: the pinned release as described, with a `passthru.tests.version` or a `checks` entry that runs `bend version` and asserts the output contains `2.0.39`.
- `packages.x86_64-linux.openspec`: OpenSpec 1.16.0 as described.
- `devShells.x86_64-linux.default`: `bend`, `openspec`, `clang` (the newest clang in the pinned nixpkgs; record its version), `qemu`, `nodejs` (22 or newer), `bun`, `python3`, `git`, `gh`, and `gnumake`, with `BEND_NO_TELEMETRY=1` exported in `shellHook` and a one-line banner printing the Bend and OpenSpec versions.
- `formatter` set to `nixpkgs-fmt` or `alejandra` (pick one, record it).

Run `nix flake check` (expect the version check to pass), `nix develop --command bend version`, and `nix develop --command openspec --version`. Record the three commands and their outputs in `verification/nix-shell.txt`.

Add a section "Nix" to `docs/INSTALL.md` after the manual install section: how to enter the shell, that the manual instructions remain valid and describe the same pinned versions, and the flakes-enablement note if needed.

Acceptance: `nix flake check` passes; the two `nix develop --command` outputs show `2.0.39` and `1.16.0`; the evidence file and the INSTALL section exist; `flake.lock` committed.

### Task 2: Reproducible library builds and checks

Add to `flake.nix`:

- `packages.x86_64-linux.tests-native`: a derivation that runs `bend Tests.bend -o $out/bin/tests-native` with `CC` set to the shell's clang, from the repository source filtered to the `.bend` files and the directories they import (use `lib.cleanSource` or `lib.fileset`; exclude `contrib/`, `docs/`, `openspec/`, `verification/`, and `.superpowers/`). Set `HOME` to a writable temporary directory inside the build because the Bend compiler may write a cache.
- `packages.x86_64-linux.examples-native`: the same for `Example.bend`, `examples/Flow.bend`, `examples/Transfer.bend`, and `GpuExample.bend`, each as a binary under `$out/bin/`.
- `checks.x86_64-linux.tests-js`: runs `bend Tests.bend` on the bundled JavaScript runner and fails unless the output ends with `ALL LIBRARY TESTS PASSED` and contains 638 lines beginning with `PASS`.
- `checks.x86_64-linux.tests-native`: runs the `tests-native` binary with `+RTS --threads 4 --gpu off` and applies the same assertion.
- `checks.x86_64-linux.proofs`: runs `bend PROOF.bend` and fails unless it prints `ALL PROOFS CHECK`.
- `checks.x86_64-linux.openspec`: runs `openspec validate --all --strict --no-interactive` over the `openspec/` directory and fails on any failure line.

Run `nix flake check` and record the output in `verification/nix-checks.txt`. Produce the determinism evidence in `verification/nix-determinism.txt` as the constraints describe. If any check cannot pass inside the sandbox for a reason you can name (for example the compiler needs network access), record the exact error, mark that check as excluded with the reason in a comment in `flake.nix`, and report DONE_WITH_CONCERNS.

Extend the "Nix" section of `docs/INSTALL.md` with `nix build .#tests-native` and `nix flake check`, and state that these reproduce the recorded verification on the pinned toolchain.

Acceptance: `nix flake check` passes or every exclusion is recorded with its error; `nix build .#tests-native` twice yields identical hashes recorded in the evidence file; INSTALL section extended.
