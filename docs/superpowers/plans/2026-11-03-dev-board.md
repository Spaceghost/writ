# Plan: Dev board, a live view of specs, explainers, and lane progress

Purpose: one locally served page that shows every OpenSpec baseline and change with its status, renders each change's markdown and its `explainer.html` pages, and shows the progress of parallel work lanes (branches, worktrees, ledgers, task checkboxes, verification files), updating live as files change. It replaces reading ad-hoc HTML files. It is development tooling, like the OpenSpec CLI, not part of Writ's enforcement runtime.

## Global Constraints

- Location: `contrib/board/`, following the precedent of `contrib/rclone/` for non-Bend tooling that the core never depends on. Add a `contrib/board/AGENTS.md` stating that the board is tooling, reads the repository and sibling worktrees read-only, and makes no authority or verification claim. Nothing under the repository root outside `contrib/board/` may be modified by this plan except `README.md` (one link line) and `.gitignore` if needed for `contrib/board/node_modules`.
- Runtime: Bun (installed at `~/.bun/bin/bun`) and TypeScript. Frontend: Datastar, loaded from a pinned CDN URL recorded in the page, with the pinned version written in `contrib/board/README.md`. Determine the current stable Datastar version from its official site or repository and record where you found it; do not guess. No other frontend framework. Markdown rendering may use one pinned npm package (for example `marked`), recorded in `package.json` with a lockfile committed.
- The board is read-only over the filesystem. It never writes to the repository, never runs `git` commands that mutate, and never executes files it reads.
- Configuration by flags: `--root <repo>` (default `.`), `--lanes <dir>` (optional; a directory whose subdirectories are git worktrees of the same repository), `--port` (default 4242), `--host` (default `127.0.0.1`). Bind only to the given host.
- Live updates: watch the root and lanes directories with `fs.watch` (recursive) debounced to about 200 ms, and push updates over one Datastar SSE connection per client using Datastar's fragment-merge events. A client that reconnects gets a full render. No polling from the browser.
- Keep it small: one server file, one page template, one CSS file, one small client script if Datastar's attributes are not enough. Prefer server-rendered HTML fragments over client state.
- Evidence: a `contrib/board/README.md` with the run command, a screenshot is not required, and a smoke test script `contrib/board/smoke.ts` that starts the server on a free port, fetches `/` and `/api/changes`, and asserts the change list contains `add-bend-runtime-host-profile`. Run it and record the output in the report.
- Do not push. Commit on the current branch only.

### Task 1: Server, index, and change pages

Create `contrib/board/server.ts` (Bun) that:

1. Scans `<root>/openspec/specs/*/spec.md` (baseline capabilities) and `<root>/openspec/changes/*/` (pending changes; skip `archive/`). For each change read `.openspec.yaml` for `x-status` and `x-depends-on`, `proposal.md`'s first heading as the title, `tasks.md` to count `- [ ]` and `- [x]` boxes, and list any `*.html` files in the change directory.
2. Serves `/` as an index: two tables (baselines; changes with status, task progress as `done/total`, dependency count, and links), plus a lanes panel (Task 2) that renders empty when `--lanes` is absent.
3. Serves `/change/<name>` rendering `proposal.md`, `design.md`, `tasks.md`, and each `specs/*/spec.md` as HTML sections in that order, with a tab or link per `*.html` explainer that serves the file at `/change/<name>/html/<file>` as-is (the explainer pages are standalone HTML; serve them with `text/html`, no wrapping, in an `iframe` on the change page or as a direct link; choose the one that keeps the explainer's own styles intact and say which in the README).
4. Serves `/spec/<name>` rendering a baseline spec and linking its `openspec/traceability/<name>.md` if present.
5. Serves `/api/changes` as JSON for the smoke test.
6. Serves `/events` as a Datastar SSE stream (Task 2 wires the watching; in this task it may send one full-render fragment on connect and keep the connection open).

Page shell: a small CSS file with light and dark via `prefers-color-scheme`, a left list of changes grouped by status, the content on the right, readable at a phone width. Use the same muted palette as the explainer pages (slate neutrals, a green accent) so the board and the pages feel like one tool.

Write `contrib/board/README.md` (run command, flags, what it reads) and `contrib/board/AGENTS.md`. Write `smoke.ts` and run it.

Acceptance: `bun contrib/board/server.ts --root .` serves the index with every change listed and the runtime-profile change page shows its proposal and its `explainer.html`; `smoke.ts` passes; lockfile committed.

### Task 2: Lanes panel and live updates

Add the lanes panel. For each subdirectory of `--lanes` that contains a `.git` file or directory, show: directory name, current branch (read `.git` worktree metadata or run read-only `git -C <dir> rev-parse --abbrev-ref HEAD` and `git -C <dir> log -1 --format='%h %s %cr'`), the SDD ledger if present at `<dir>/.superpowers/sdd/*/progress.md` (render its last ten lines), each `<dir>/.superpowers/sdd/*/task-*-report.md` as a collapsible section rendered from markdown, the task checkbox counts for every change directory in that worktree that differs from the root's counts, and the list of files under `<dir>/verification/` newer than the root's copies.

Wire live updates: watch `<root>/openspec`, `<root>/verification`, `<root>/docs`, and every lane directory's `openspec`, `verification`, `docs`, and `.superpowers/sdd` subtrees. On change, re-render the affected fragment (index tables, a change page, or the lanes panel) and push it as a Datastar fragment-merge on every open `/events` connection whose page includes that fragment. Debounce about 200 ms. Ignore `node_modules`, `.git`, and build directories.

Extend `smoke.ts`: after the first fetch, touch a temporary file under a temporary `--lanes` directory's `verification/` and assert that an SSE event arrives within two seconds. Clean up the temporary directory.

Add one line to the repository `README.md` under "Read further" linking `contrib/board/README.md`.

Acceptance: with `--lanes ../writ-lanes` the panel lists each worktree with branch, last commit, ledger tail, and reports; editing a report file updates the open page without reload; `smoke.ts` passes including the SSE assertion.
