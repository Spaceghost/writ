A reading order that works

  1. Guard.bend, then LAWS.bend and PROOF.bend. Thirty lines of code and three laws teach the no-if style, the Checks fold, and what a proof looks like.
  2. examples/Expect.bend then examples/Flow.bend. An IO block driving the real library with the smallest scenario.
  3. Core.bend top to bottom. The records and the comments on each one explain edge direction, what the monitor supplies, and why indexes are walked rather than wrapped.
  4. examples/Scenario.bend. Every synthetic record the examples share, each named for its role in the story. Follow any helper into its component module when you want the real type.
  5. DataOS.bend. Short, and it shows how the facade threads the capability check into Backplane.commit.
  6. examples/Commit.bend with openspec/STATE-MACHINES.md open beside it. That is the whole negotiation, including the revoked-capability branch.
  7. Only then Transfer.bend, Negotiation.bend, Backplane.bend. They are long because every gate is explicit.

Public entry points versus exported helpers

Bend exports every definition in a module. The docs draw a hard line between the calls a host is meant to use and the internal steps whose preconditions are set by their callers. Names like *.checked, *.finish, *.result, and *.go are implementation steps, never alternate release routes.

CallReturns
Core.solve_cpu(graph, max_rounds)Solved{candidate, rounds} or SolveFailed{reason}. 0n picks the N+1 sweep bound.
Core.verify(original, candidate, live_stamp)Approved{} or Denied{reason}, independent of the solver.
Core.authorize_sink(graph, candidate, stamp, sink)Adds the destination's clearance, tolerated influence, and actual effect check.
Dlm.flows(snapshot, epoch, source, dest)Bool finite-DLM flow decision.
Transfer.admit(plan, live_context)Admitted{Ticket} or Denied{reason}.
Negotiation.pin / challenge / sample / approve / reserve / startGuarded transitions; failure returns the supplied session unchanged.
Frontend.checked_plan(...)The exact capability-bound plan or None{}.
Backplane.commit(...)Updated session and ledger plus WriteIntent, or Rejected{session, ledger}.
DataOS.commit_from_capability(...)Fresh descriptor and caller checks, then the whole backplane. The host-facing route.

How tests are built

There is no test framework. Test.bend defines one function, check(ok, name), which prints PASS: name or dies with status 1. Each *Tests.bend module has a main that runs its checks in an IO block, and Tests.bend imports all nine and calls them in order, finishing with ALL LIBRARY TESTS PASSED.

# Tests.bend, in full
import ./CoreTests.bend as Core
import ./TransferTests.bend as Transfer
# ... seven more

def main() -> IO(Unit):
  do IO<Unit>:
    Core.main()
    Transfer.main()
    # ...
    IO.print("ALL LIBRARY TESTS PASSED")

Counting both PASS: and PASS lines yields 638 per backend. The recorded suite was run on the JavaScript backend under Node and as a native binary on four threads with the GPU off. Today's run on this machine matched: the suite ended with the final line above and PROOF.bend printed ALL PROOFS CHECK.

Examples are deliberately not tests. They import no *Tests.bend file, build their own clearly marked synthetic records, and must exercise both a permitted and a denied outcome. If you add an example, update its explanation and the captured output in examples/README.md together.

OpenSpec: contracts beside code

Behavior changes start in openspec/. Current contracts live in openspec/specs/, one capability per directory, each paired with a traceability table in openspec/traceability/ mapping requirement IDs to Bend functions and named tests. Proposed behavior lives in openspec/changes/ as proposal, design, tasks, and delta specs. A scenario in a spec is an acceptance contract; it is not evidence that a test exists.

npm install -g @fission-ai/openspec@1.16.0
openspec validate --all --strict --no-interactive   # structural only; not a Bend test
openspec show transfer-admission --type spec
openspec status --change add-authenticated-grant-issuance

Pending changes worth knowing about by name: authenticated grant issuance, a capability POSIX adapter, an S3 adapter, Genode, Linux and Windows hosts, a Drift kernel host, metered sample execution, policy-aware audit, and physical GPU validation.

House rules from AGENTS.md

  • Everything authored is Bend 2. Generated C or JavaScript and native binaries go outside the source tree (the docs use a sibling ../writ-build/). The only Go permitted is the rclone adapter under contrib/rclone/go/. No root Go module, no core dependency on it.
  • Pinned toolchain. Bend 2.0.39 unless you are deliberately migrating and revalidating. Read bend guide and bend guide shaders before changing language or parallel code.
  • After any meaningful security change: run bend Tests.bend, the native build of it, and bend PROOF.bend. Use --verdict if Lean is available. Report limits honestly: a CPU fallback is not a GPU test.
  • Never add: @unsafe definitions, proof holes, unchecked array indexes, alternate release routes, automatic declassification, or caller-controlled authority facts.
  • Keep the verifier independent of solver work lists. Revalidate capabilities, epochs, inherited restrictions, budgets, and exact scope at commit.
  • Changing a law needs a written rationale. Never weaken one to make a changed implementation pass.
  • Comments explain authority, invariants, edge direction, and failure behavior, not what an expression computes. Document public entry points and distinguish them from exported helpers.
  • Comment-only cleanups are checked by diffing implementation tokens against the prior revision, and the source manifest in verification/source-sha256.txt must match the delivered tree.
  • Host platforms: read docs/PLATFORMS.md first. Host qualification evidence is separate from library tests; a model test never hides a missing native control.

# specs
openspec validate --all --strict --no-interactive

Backplane: a large Bend app to learn from

You asked for the i2cjak Backplane source. It was not on disk, and the project has moved: the GitHub redirect from i2cjak/Backplane now lands on BackplaneWorks/Backplane. The latest main is cloned at:

~/src/github.com/BackplaneWorks/Backplane     # 3,695 commits, HEAD 18e9f71 from 2026-11-03

Backplane is an agentic hardware development workspace: an agent edits KiCad and FreeCAD files while you follow in board, schematic, and 3D viewers. The hub, viewers, and clients are a ground-up rewrite in Bend, around 1,180 .bend files. Its own AGENTS.md opens with the same advice as Writ's: run bend guide, keep rules in LAWS.bend, run bend PROOF.bend before committing, parallelize when possible.

Layout to study

  • src/core/: pure Bend, no IO. JSON, S-expressions, the event-sourced thread model, KiCad parsing, scene diff, semver, prompt logic.
  • src/server/: the one Bend program that owns IO. HTTP and WebSocket, event store, agent processes, git, file watching. Custom effects are JavaScript in src/server/effects/*.js; the hub runs on Bun.
  • src/web/, desktop/, mobile/: clients. Bend files alongside JS, Swift, and Kotlin shells.
  • test/: Bend tests plus Python and TypeScript tooling tests.

Law-driven development at scale

  • LAWS.bend holds 3,165 laws over the real code, about 16,000 lines; PROOF.bend matches it line for line.
  • Laws are small and concrete: settle_at_window, semver_pre_before_release, string_eq_refl. A module's header comment names the laws that govern it.
  • scripts/laws-shape.py is a one-second structural check that needs no Bend. scripts/merge-laws.py is a block-wise git merge driver, because merge=union mangles proof files.
  • Humans own LAWS.bend; an agent may add a law but never weaken or delete one without consent. Writ's rule is the same.

What to borrow, and what differs

  • Borrow: the strict pure-core / IO-shell split. Writ already does this (the library is pure; only examples and tests touch IO), and Backplane shows it holding up across a real server.
  • Borrow: the habit of writing a tiny law next to each nontrivial helper, with the module comment naming its laws. Writ has three laws today; there is room for more of this style.
  • Borrow: reading src/core/semver.bend as a model of idiomatic small Bend: Nat.read into Maybe, +i <> t list patterns, and .k-suffixed continuation helpers that exist because match cannot inspect a computed value.
  • Differs: Backplane writes its effects in JavaScript and runs on Bun. Writ forbids non-Bend implementation and uses only Base's built-in IO; any host adapter is a separate contribution with its own evidence.
  • Differs: Backplane tests live under test/ with a mixed toolchain. Writ keeps a flat *Tests.bend pair per module, a dated verification record, and OpenSpec traceability.

A note on scale: Backplane's AGENTS.md is long and specific to its own release process. Skim its first sixty lines and the src/core directory listing; that is where the transferable Bend craft is. The telemetry, packaging, and mobile sections are not relevant to Writ.
