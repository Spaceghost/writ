Every qemu/x86_64 image made from hosts/unikraft/app/ is built with these two settings;
they are pins in the same sense as the versions above (changing either changes what the

  1. The experimental posix signal library, in the template Kconfig:
     hosts/unikraft/app/Kraftfile   CONFIG_LIBPOSIX_PROCESS_SIGNAL: 'y'
       ea31944043807789720f42c2267bb16082b4b177e6164a6dc2eba6299390a4ce  hosts/unikraft/app/Kraftfile
     Kconfig entry in the pinned core: $W/src/unikraft/lib/posix-process/Config.uk:78
       config LIBPOSIX_PROCESS_SIGNAL / bool "POSIX signals (EXPERIMENTAL)", which selects
       LIBPOSIX_PROCESS_MULTITHREADING, LIBPOSIX_PROCESS_EXECVE, LIBUKLOCK and
       LIBUKLOCK_SEMAPHORE. Resolved .config in every set built with it:
       CONFIG_LIBPOSIX_PROCESS_SIGNAL=y, CONFIG_LIBPOSIX_PROCESS_EXECVE=y, CONFIG_LIBUKBINFMT=y,
       "# CONFIG_LIBPOSIX_PROCESS_SIGNALFD is not set".
  2. The build flag, in hosts/unikraft/scripts/build.sh:
     UK_CFLAGS="-std=gnu11 -include uk/config.h"
       67ceb9d2b074ec39b7d0c3f9918022974e3fe38af7954b17c1b3bbe1a4fc2817  hosts/unikraft/scripts/build.sh
     -std=gnu11 as before; -include uk/config.h works around 0.21.0's include order in
     lib/posix-process/shutdown.c (signal/signal.h at :11 before <uk/config.h> at :14, so
     signal.h:116's CONFIG_LIBPOSIX_PROCESS_MULTITHREADING guard reads 0 and the
     pprocess_signal_send declaration at :287 is skipped; shutdown.c:63 then fails to build).
     No Unikraft source is patched. The flag applies to every compilation unit of every image.
Sets built with both (all in $W, made by mkapp.sh from the template):
  sigfault, sigcodes (Task 1: verification/unikernel-fault-qemu.txt)
  sigeffects (verification/unikernel-effects-qemu.txt), sigchannel

Every clean build fetches the musl tarball again from musl-libc.org (lib-musl's build); in
