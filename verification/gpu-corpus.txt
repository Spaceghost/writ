## Limits

- The launch count attributes device execution to the single bang site (BANGS 1), not to individual test cases. It does not show that every Gpu.solve_gpu call in the corpus dispatched (CoreTests' "empty parallel graph needs no dispatch" case is designed not to), nor which of the 4915 launches belong to which test. Launch grids were (1,1,1) for 1966 and (128,1,1) for 2949 launches; the mapping of launches to sweeps was not established.
- Label and transfer batches in the corpus are host-side calls without `!`; the corpus does not exercise them on the device. Device evidence for those two paths is in verification/gpu-paths.txt, gpu-parity.txt and gpu-injection.txt, not here. (Task 9: the Limits bullet the Task 6 review asked for.)
- The `--gpu on` captures and the plain pass are device runs not individually observed; the observed passes are separate runs of the same binary whose stdout is byte-identical. observe.sh's passes use 32 threads, not the captures' 4; the `--threads 4` options are covered by a supplementary sanitizer run that is not a gate record.
- The corpus checks its own GPU solver results against Core.solve_cpu (and the property cases against CPU and Bend parallel producers) in-process; it adds no independent verifier pass beyond what the tests already contain. Library correctness here means the corpus's 782 checks pass and its output is byte-identical to the CPU reference; it says nothing about paths the corpus does not exercise.
- The pmon and utilisation samples are not gate inputs for this run (plain pass under 10 s); the utilisation reading is global and shared with the display.
- The `--gpu off` capture's CPU execution is shown by the off sanitizer run (exit 255, "Target application terminated before first instrumented API call", 0 launches), consistent with verification/gpu-gate-controls.txt (b).
- Not exercised: `--gpu <size>` heap options (no exhaustion occurred), the default (no +RTS) mode, CUDA_VISIBLE_DEVICES set, the JavaScript backend, proofs, and `--verdict` (Lean is absent). Nsight Systems and Nsight Compute are not installed, so there is no host/device time split.
