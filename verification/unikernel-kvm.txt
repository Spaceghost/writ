== Harness ==

hosts/unikraft/scripts/run.sh takes an optional 8th argument, accel: tcg (default, -accel tcg
-cpu max, logged command unchanged) or kvm (-accel kvm -cpu host). Every KVM boot below is
  hosts/unikraft/scripts/run.sh <set> <label> <probe> "+RTS --threads 1 --gpu off" <T> <M> "" kvm
followed by the unchanged check script on that capture with WRIT_NO_BOOT=1 (check-image.sh,
check-fault.sh, check-corpus.sh), so the checks are exactly the TCG ones. The logged command
(run-kvm-hello1.log):

== Fix round (2026-11-05 UTC): the kernel shutdown fragment rule ==

Ruling (controller): do not change exit_device.c now; make the checks honest about the one
known kernel line. The rule, as tightened in Fix round 2 (below; this round's first
definition, "a prefix of the pm.c line" with a loose timestamp, is superseded): a trailing
unterminated fragment that is the start of a timestamped kernel line after the exit write
(a cut-off timestamp, or the pm.c:69 line) is dropped, and counted every time.
check-image.sh (and so check-corpus.sh) drops it from the raw capture before console.sh;
check-fault.sh drops the matching last program line, before its own "[ <s>] " filter, so a
whole timestamped line is counted rather than dropped silently. Nothing else is dropped.
Each prints "kernel shutdown fragment after exit: dropped <0|1>".

Limit of the rule: a fragment cut inside the timestamp ("[  ", "[    0.133495] ") is a
prefix of the pm.c line and also of any Unikraft log line, so it cannot be attributed to
pm.c by its text. On the normal-shutdown boots pm.c's line is the one uk_pm_shutdown prints
next; on kvmfix-overflow1 (crash path) the dropped "[    2.27112" is the start of a further
crash-screen line, not a pm.c line (it would have failed check-fault.sh's program-line check
without the rule). The count shows every such drop.

Helper unit check of the first definition (superseded; the review found it also accepted
"[1.5]", "[12", "[1", "[5.25]", "[ 1.0]", "[3.0] E", "["; see Fix round 2): yes for "[", "[  ",
"[    0", "[    0.13", "[    0.133495]", "[    0.133495] ", "[    0.117238] ERR:  [li", the whole

unterminated last line (NUL or CR only), is not dropped and so fails the check (the safe
