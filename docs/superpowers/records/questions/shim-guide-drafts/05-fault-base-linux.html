Shim review 5 of 9: the fault decision and the base-linux SIGSEGV path

On base-linux, Genode components are ordinary Linux processes, and an unpopulated part of a reservation is a PROT_NONE Linux mapping. Touching it raises the Linux signal SIGSEGV. A signal handler here means a Linux one: a function the kernel runs on the faulting thread. (Genode also has its own Signal_handler, an asynchronous notification dispatched by an entrypoint. That one appears on page 6.) Genode's own region-map fault notification is never delivered on base-linux (header 76-83). So the shim installs a raw SIGSEGV handler with the rt_sigaction system call, replacing base-linux's handler for the whole process (88-89). Both platforms share one decision function, _resolve_fault (688-696). Read it first. It is the only place that chooses between "populate" and "refuse". Then read the Linux front end. The base-linux row of INVENTORY.md:274 ("Fault delivery" table) and the concurrency note at :689-705 describe it.

Open: writ_mem.cc:76-94, writ_mem.cc:213-239, writ_mem.cc:305-375, writ_mem.cc:487-541, writ_mem.cc:680-776

Each claim below shows the lines that carry it (line number, tab, source; tabs in the source shown as four spaces), what I see there, and my recommendation. Nothing is pre-selected: read the lines and choose.

Claim 1

_resolve_fault has exactly four outcomes (outside, guard, already populated, populate or _populate's refusal) and reads only the reservation's size, guards, and chunk table.

680	/*
681	 * The population decision both front ends share (caller holds _mutex).
682	 * off is the faulting offset inside r. Returns the refusal reason, or
683	 * nullptr when the fault is resolved: either the chunk at off was
684	 * populated now (counted in _faults_resolved) or it was already populated
685	 * (populated set, nothing done; each front end decides what that means,
686	 * see "Retry table" in the header).
687	 */
688	static char const *_resolve_fault(Reservation &r, addr_t off, bool &populated)
689	{
690	    if (off >= r.size)  return "outside every reservation";
691	    if (r.in_guard(off)) return "guard page";
692	    if (r.chunks[off/CHUNK].populated) { populated = true; return nullptr; }
693	    if (char const *why = _populate(r, off)) return why;
694	    _faults_resolved++;
695	    return nullptr;
696	}

What I see. This is the one place either platform chooses between "populate" and "refuse", and its inputs are an offset and the shim's own tables. No identity, label, or Bend state is reachable from here. Refusing a guard touch is the guard's purpose, not a choice.

Recommendation: Confirmed, four outcomes, no outside input.

Claim 2

A SIGSEGV not generated by the kernel (si_code <= 0, from kill/tgkill/sigqueue) is not treated as a fault: the default action is restored and the signal re-raised on the thread.

711	static void _segv_handler(int, Lx_siginfo *info, void *)
712	{
713	    /*
714	     * si_code <= 0: sent by kill/tgkill/sigqueue, not a memory fault.
715	     * Returning would not re-raise it, so take the default action now.
716	     */
717	    if (info->code <= 0) {
718	        raw("writ_mem: SIGSEGV not from a fault (si_code ", info->code,
719	            "), component terminates");
720	        Lx_sigaction dfl { (void (*)(int, Lx_siginfo *, void *))LX_SIG_DFL,
721	                           0, nullptr, 0 };
722	        lx_rt_sigaction(LX_SIGSEGV, &dfl);
723	        lx_syscall3(LX_SYS_TGKILL, lx_syscall3(LX_SYS_GETPID, 0, 0, 0),
724	                    lx_syscall3(LX_SYS_GETTID, 0, 0, 0), LX_SIGSEGV);
725	        return;
726	    }

What I see. The check comes before any lookup, so a signal sent by another process cannot make the shim map memory. The response is fixed: restore the default action, re-raise, and the process dies as Linux would have killed it.

Recommendation: Confirmed, the early branch is unconditional on anything but si_code.

Claim 3

The base-linux refusal prints one raw line, restores the default SIGSEGV action, and returns; the retried access then kills the process. Nothing on this path populates a guard or maps memory elsewhere.

703	{

705	        "), component terminates");
706	    Lx_sigaction dfl { (void (*)(int, Lx_siginfo *, void *))LX_SIG_DFL,
707	                       0, nullptr, 0 };
708	    lx_rt_sigaction(LX_SIGSEGV, &dfl);
709	}
728	    addr_t const a = addr_t(info->addr);
729	
730	    Mutex::Guard guard(_mutex());
731	
732	    Reservation *r = _lookup(a);
733	    if (!r) { _refuse("outside every reservation", a); return; }
734	
735	    bool populated = false;
736	    if (char const *why = _resolve_fault(*r, a - r->base, populated)) {
737	        _refuse(why, a); return; }

What I see. _refuse touches no reservation state. Returning from the handler retries the faulting instruction, which faults again with the default action in place, and Linux terminates the process. There is no alternative outcome on this path. The documented limits (handler on the faulting stack, so a stack overflow dies without the line; deadlock if the faulter holds the mutex) are recorded in the header (213-238) and in INVENTORY.md:689-705.

Recommendation: Confirmed, the refusal ends the process and does nothing else.

Claim 4

A fault on an already-populated chunk is retried only while _retry_allowed allows (at most 16 per page in 16 round-robin slots), and refused after that.

512	    addr_t const page = a & ~addr_t(PAGE - 1);

515	            return ++e.count <= MAX_RETRIES;

739	    if (populated) {

What I see. This is the memory half's clearest "decides to kill" rule, and I read it as a bounded mechanical limit. It exists only so that a fault the shim cannot fix does not loop forever, and it reads nothing but a page address and a counter. Its known flaws are mechanical too: a page that races harmlessly more than 16 times over a reservation's life is killed, and more than 16 stuck addresses can evict each other and livelock (494-501). Neither involves a Writ fact; both are availability limits.

Recommendation: Confirmed, the cap and its stated limits match the code.
