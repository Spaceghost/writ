Runtime handler under test (Bend 2.0.39 emitted C): pool_stack() maps a 2 GiB stack plus a 16 KiB
PROT_NONE guard and installs err_trap for SIGSEGV and SIGBUS on an alternate signal stack;
err_trap writes "bend: memory fault (machine stack overflow?)" to fd 2, restores SIG_DFL, and
re-raises the signal, so the process ends by SIGSEGV (shell status 128 + 11 = 139).

## Where the fault lands (gdb, depth 10^9)
$ gdb -q -batch -ex 'handle SIGSEGV stop nopass' -ex 'run +RTS --threads 1 --gpu off' \
    -ex 'p $_siginfo._sifields._sigfault.si_addr' -ex 'bt 3' -ex 'info proc mappings' \
    ../writ-build/runtime-profile/overflow/overflow-1000000000
Excerpt of the output:
Program received signal SIGSEGV, Segmentation fault.
0x00005555555594b8 in WL_FID_climb ()
$1 = (void *) 0x7ffff79ee000
#0  0x00005555555594b8 in WL_FID_climb ()
#1  0x000055555555912d in work_loop ()
#2  0x0000555555556b8a in corpus_eval ()
0x00007fff779ee000 0x00007ffff79ee000 0x80000000         0x0                rw-p
0x00007ffff79ee000 0x00007ffff79f2000 0x4000             0x0                ---p
The faulting address is the first byte of the 16 KiB PROT_NONE guard directly above the 2 GiB
(0x80000000) read-write evaluation stack, raised from climb's work-loop case. So the fault is the
evaluation stack walking into pool_stack's guard, not an unrelated bad access. (Under gdb the
signal is stopped before delivery; the runs above, without gdb, show the handler's behaviour.)

## Result
Depths of 10^6, 10^7 and 10^8 return and print their count. At 10^9 the recursion reaches the
guard page (located below): the runtime prints its own message "bend: memory fault (machine stack overflow?)" on
stderr, stdout is empty (the count was never printed, so execution did not continue past the
fault), and the process ends with status 139 (SIGSEGV re-raised under SIG_DFL), which is nonzero.
The fault took well under the one-minute bound. This is CPU execution on one Linux host; it says
nothing about whether another host delivers the signal (RH-006's second scenario is not tested).
