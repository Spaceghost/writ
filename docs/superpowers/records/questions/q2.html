Adopt the experimental Unikraft signal library for the fault message?

UL-006 wants a fault to halt with a distinct code and the runtime's own message. The trial showed the message (bend: memory fault (machine stack overflow?)) appears only with CONFIG_LIBPOSIX_PROCESS_SIGNAL, which Unikraft 0.21.0 marks experimental and which does not compile as shipped (it needed -include uk/config.h). Adopting it means an experimental library in every image, a permanent build flag, a change to how shutdown works, and another 95-minute corpus rebuild. Without it the delivered images crash silently but still exit with the distinct code 253.

Either way, arena exhaustion stays a crash (253): the guest runs out of memory backing the arena before the runtime's own check is reached. That half of UL-006 needs a different idea (a smaller arena or a guard on the arena's end).
