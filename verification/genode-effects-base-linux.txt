HOW THE EFFECTS ARE REGISTERED (bend guide effects)
  `bend guide effects`, sections "An effect def" and "The C side": an effect
  is a def of type IO(R) whose body is two imports, a .c and a .js file; the
  compiler splices the .c file into the program's C after the runtime, and
  the file registers the effect in a constructor with
  io_eff(CID(Name), run). CID(Name) is read "in the effect's namespace
  first (the file that declares the def)". "Blocking work leaves the loop
  in two ways. io_work(w, call, pack) runs call(w) on a helper thread, then
  pack(e, w) on the loop ... call has no Env: it may only touch w." No
  runtime edit was needed: the 2.0.39 toolchain registers the three custom
  effects as written.
  Observed in probe.c: the twins are spliced at lines 3834-3899; the
  registrations read
    io_eff(CID____effects_Genode_Genode_log, genode_log_run);
    io_eff(CID____effects_Genode_Genode_now, genode_now_run);
    io_eff(CID____effects_Genode_Genode_sleep, genode_sleep_run);
  (the compiler mangles the declaring file's path relative to the importer
  into the C id; the Bend names are Genode.log, Genode.now, Genode.sleep,
  called as Host.Genode.* through the import alias).
  Import form: `import ../effects/Genode.bend` without an alias is refused
  ("expected: an import ('import Base', or 'import <path> as <Name>')"), so
  Probe.bend uses `as Host`.
  JS twins: `bend hosts/genode/monitor/Probe.bend` (the JavaScript runner)
  stops at the first effect with
    Error: Genode.log: the JavaScript runner is not a Genode target; build
    with bend -o <name>.c and link the Genode shim (hosts/genode/)
