Shim review 9 of 9: queue, take, put, and the transport refusal

This is the data path. A client writes a 64-byte record (16 words) after a 16-byte header into its request bucket, then signals. The writ_channel entrypoint queues one entry per channel in an 8-slot ring (1503-1519) and wakes a semaphore. writ_shim_take runs on a Bend runtime helper thread. It blocks on that semaphore, pops one entry, copies the record out once, and returns the record, the channel id, and the route subject stored at session creation. writ_shim_put copies Bend's reply into the result bucket without reading it and signals the client. One result is written by the shim itself: if the header length is not exactly 64, a fixed refusal record. GB-006's own scenario requires that ("dropped, counted, and answered with a fixed transport refusal before any Bend parsing"). See INVENTORY.md:87-88, :201-211, and the channel bounds at :409-455.

Limit or policy? The length gate (1751-1756) is the one place the shim answers a client without Bend, so ask whether it is an alternate release decision. It is a fixed transport check. It depends only on the length word, and the record it writes (1674-1686) is the same for every channel and subject. Its kind, decision, and reason words (3, 3, 256; 1412-1416) are outside the monitor's (kind 2, decisions 1 and 2, reasons 0 to 8), so it cannot be read as a Writ outcome. Signal coalescing (1510) drops no data, because the bucket is read at take time. The close event (1727-1735) translates a native fact, a session closing, into subject 0, which no open channel can have.

Confirm by reading:

  1. take copies exactly 16 words, once, after an acquire fence, and only when the length is exactly 64 writ_mem.cc:1742-1759; Bend sees only that copy.
  2. The subject returned to Bend is the one stored at session creation (1513, 1765), never a word from the bucket; a close event returns subject 0 and an all-zero record writ_mem.cc:1727-1735.
  3. A wrong length is counted, warned, and answered with the fixed record from _channel_refuse writ_mem.cc:1674-1686, which depends on nothing but the request's sequence number, and never reaches Bend.
  4. put writ_mem.cc:1775-1796 copies Bend's record without inspecting it, writes the sequence number and then the length after a release fence, and is skipped (counted) for a closed channel or one with no taken request; writ_mem_report (1798-1842) only reads counters and logs.
