Failure path observed (first attempt, before the fix now in writ_hello.run):
the wait pattern was "writ_hello: component constructed on Genode\n". The
line was printed, but the pty delivers "\r\n", so the pattern never matched:

  [init -> writ_hello] writ_hello: component constructed on Genode
  Error: Test execution timed out
  make: *** [etc/build.conf:155: run/writ_hello] Error 254

The pattern now ends ".*\n", as upstream log.run's does. This also shows the
run script exits nonzero when the expected line is not matched within the
timeout. After both runs, no core/init/component processes remained (pgrep).

== Limits ==

- Genode-on-Linux only (base-linux). Says nothing about base-hw, NOVA, or
  any native kernel, and nothing about Writ's own Linux host profile.
- Seccomp check (separate manual start, not part of the run script):
    cd ../writ-genode/build/x86_64/var/run/writ_hello/genode
    timeout 4 ./core &   # then, 2 s later, /proc/<pid>/status of core's children
  result:
    [Genode] init                 NoNewPrivs: 1  Seccomp: 2 (filter)
    [Genode] init -> writ_hello   NoNewPrivs: 1  Seccomp: 2 (filter)
    core (core-linux)             NoNewPrivs: 0  Seccomp: 0
  So components start under no_new_privs and a seccomp filter; core does
  not. The filter's contents were not inspected.
- writ_hello stays resident after construct() returns (normal for a Genode
  component); the run tool and timeout end the scenario, not the component.
- tool/run/run was invoked through nixpkgs expect 5.45.4 via an authored
  build.conf rule, because the host has no /usr/bin/expect and no root.
  The upstream tree is unmodified.
