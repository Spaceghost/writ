# Plan: Unikraft lanes behind the thread library (task 2.4)

Spec: `openspec/changes/add-unikernel-library-runtime/` (UL-005, task 2.4). The shipped image is a declared single-lane configuration: `CONFIG_UKPLAT_CPU_MAXCOUNT: 1`, Unikraft 0.21.0's only scheduler (`ukschedcoop`, cooperative), `+RTS --threads 1`. The one earlier try at `--threads 2` on one CPU created a lane whose `pool_work` was never entered before shutdown in a non-yielding program (E6, `verification/unikernel-effects-qemu.txt`; `docs/UNIKERNELS.md` "A declared single-lane configuration"). Task 2.4 asks for lanes behind the kernel's thread library with corpus parity and a recorded lane count. This plan is a time-boxed, evidence-first chase: either the corpus matches on two lanes over two vCPUs, or the exact stopping point is recorded and the box stays open.

### Task 1: Two lanes on two vCPUs with a probe

Add the vCPU option to `run.sh` (`-smp N`, default 1, so every existing call is unchanged) and the lane and vCPU pass-through to `check-corpus.sh`. Create set `lanes` from the template with `CONFIG_UKPLAT_CPU_MAXCOUNT: 2` (the Kconfig symbol is `UKPLAT_CPU_MAXCOUNT`, `plat/Config.uk:18`; `HAVE_SMP` at :23 is selected by the platform, check it resolves to y in the set's `.config` and record it). Build the hello probe and run it four ways: `--threads 1` on `-smp 1`, `--threads 1` on `-smp 2`, `--threads 2` on `-smp 1`, `--threads 2` on `-smp 2`, with a 120 s timeout each; record for each the console lines, the QEMU exit code, and whether the program's output is complete. Then a probe that makes the lanes do work: `scripts/unikernel/` has the earlier probes; reuse the one that showed E6 (or the parity example from `verification/runtime-profile-parity-examples-4.txt`'s source if it has a Unikraft harness) so that `pool_work` is entered, and record whether the second lane ran (the runtime's own lane count output or a line per lane). If `--threads 2` hangs on `-smp 2`, record the last console line, the timeout exit (124 from `timeout`, or the harness's value), and stop the task there with status DONE_WITH_CONCERNS; do not try scheduler or runtime changes.

Acceptance: `run.sh` and `check-corpus.sh` diffs are small and backwards compatible; the four runs are recorded; the second lane is shown to run (or the stall is recorded exactly).

### Task 2: Corpus parity on two lanes

Only if Task 1 showed the second lane running: build the corpus image in set `lanes` and run `check-corpus.sh` with `--threads 2` on `-smp 2`; the program lines must equal the single-lane reference and the count be 782 PASS. Record the lane count as the runtime reports it, the wall time against the single-lane run, and the hash. If Task 1 stalled, this task instead records in `verification/unikernel-lanes-qemu.txt` the stopping point and what a fix would need (a yielding wait in the runtime's lane loop, or a preemptive scheduler Unikraft 0.21.0 does not ship), and the box stays open.

Acceptance: parity on two lanes with the count and lane count recorded, box 2.4 checked citing the file; or the stall recorded and the box left open with the reason in `tasks.md`.
