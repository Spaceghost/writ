Shim review 3 of 9: making and releasing a reservation

A qualifying mmap becomes a reservation: address space that is set aside but has no memory behind it yet. Genode terms: a dataspace is a piece of memory (or address space) that can be referenced by capability and attached into an address space. A Region_map is an address-space layout: a set of dataspaces attached at offsets. A region map can itself be exported as a dataspace (a "managed dataspace") and attached into another region map. An Rm_connection is a session to the RM service that creates such region maps. So _reserve asks the RM session for an empty region map of the requested size, attaches it into the component's own address space (Env::rm()), and records it in a fixed table of 32 slots. Nothing is populated, so no RAM is charged here. Read the table struct first (378-435), then _reserve and _release.

    /*
     * Linux treats the address as a hint: try it, then let the local
     * region map choose. The runtime compares the result with its hint
     * and unmaps a misplaced reservation itself.
     */
    Region_map_client rm(rm_cap);
    auto attach_at = [&] (bool use_at, addr_t at) -> addr_t {
        return _env->rm().attach(rm.dataspace(), {
            .size = 0, .offset = 0, .use_at = use_at, .at = at,
            .executable = false, .writeable = true
        }).convert<addr_t>(
            [&] (Env::Local_rm::Attachment &a) {
                a.deallocate = false; return addr_t(a.ptr); },
            [&] (Env::Local_rm::Error) { return addr_t(0); });
    };
    addr_t base = 0;
    if (hint && (addr_t(hint) & (PAGE - 1)) == 0)
        base = attach_at(true, addr_t(hint));
    if (base) _reserved_at_hint++;
    if (!base) {
        base = attach_at(false, 0);
        if (base) _reserved_elsewhere++;
    }
    if (!base) {
        _rm_connection->destroy(rm_cap);
        _heap->free(chunks, num_chunks*sizeof(Chunk));
        errno = ENOMEM; return MAP_FAILED;
    }

    *r = { .used = true, .base = base, .size = size, .rm_cap = rm_cap,
           .chunks = chunks, .num_chunks = num_chunks, .guards = { },
           .num_guards = 0 };
    return (void *)base;

Limit or policy? Two choices to judge. First, a hint that cannot be honoured is replaced by an address the local region map chooses (985-991). That is Linux's own mmap hint semantics, and the runtime compares the result with its hint and unmaps a misplaced one itself (969-973), so the caller still decides what to accept. Second, MAX_RESERVATION (930) also caps the runtime's corpus_grow at a 2 TiB corpus (919-929), and the 32 slots cap lanes at about 30 (INVENTORY.md:379-383). Both are fixed capacity bounds that surface as ENOMEM, which the runtime already handles as "cannot grow". No Writ fact enters either one.

Confirm by reading:

  1. Every refusal in _reserve sets errno = ENOMEM, undoes what it already built, and returns MAP_FAILED (930, 935, 946, 951, 957-958, 963-966, 992-996).
  2. A hint is tried only when it is page-aligned (985-986); otherwise, or on failure, the shim attaches wherever the local region map allows writ_mem.cc:988-991 and counts which happened. It does not refuse the call or pick a reservation for any other reason.
  3. Nothing in _reserve writ_mem.cc:916-1002 reads anything except its arguments, the slot table, and the results of Genode calls.
  4. _release writ_mem.cc:1004-1028 detaches and frees every populated chunk, destroys the region map, frees the chunk table, and (base-linux) clears the retry entries for this reservation's pages (1016-1024), so a later reservation at the same address inherits no counts.
