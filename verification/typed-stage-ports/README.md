# Synthetic typed-edge observations

For two untrusted edges into two declared ports, the [synthetic profile](../../openspec/changes/add-origin-transform-stages/typed-edge-description.md) compares each original binding and the complete projected sequence independently, then asks the existing stage-graph checker for a cycle observation. It does not authenticate declarations or admit a stage.

On 2026-11-07 local time (2026-11-08 UTC), pinned Bend 2.0.39 and generated Node each passed [52 focused checks](focused.stdout). The full suite passed 2,896 named checks on Bend, generated Node and native CPU; complete stdout matched [suite.stdout](suite.stdout). The focused stdout SHA-256 is `b60537e4ad4ee0c3a152ce460e651c423579467f098dc7045a8e301e0d1a5e2e`, and full stdout SHA-256 is `ee16d361625954079d7f5826b148e14ba7f3d7f6514e3fde0e38628b330b857c`.

The checks cover repeated stage pairs for distinct ports, missing, duplicate, extra, out-of-order and schema-mismatched bindings, coordinated substitutions, interleaving across destinations, original-edge cycle closure omitted from a supplied projection, and direct exported helper and candidate calls with 10,000-item tails. Exact description comparison is not a validity or authority gate. No extra formal law was added: ordinary `bend PROOF.bend` and the Lean-backed `--verdict` passed on existing laws, and the `/bin/false` negative control exited 1. Strict OpenSpec validation passed 45/45.

The static native CPU build used `clang -std=c11 -O0 -static ... -lpthread -lm`; the run used `+RTS --threads 1 --gpu off`. Both exited 0 with empty stderr and identical complete output. Build and run used a 600-second wall/CPU cap, 16 GiB and 20 GiB virtual-memory limits respectively, a file-size cap and disabled core dumps; each passed a 40 GiB available-memory preflight.
