Unikraft effect-twins lane, Task 2: ingress twins over a second serial channel
Recorded 2026-11-04 on Linux x86_64 (Manjaro, kernel 7.2.9), no root.

CODE MAP NOTE (2026-11-04, Unikraft effect-twins lane Task 3): the QEMU statuses below were
recorded under the exit hook's map at the time and are kept as recorded. The hook now
writes program statuses as s + 0x10 (success 33, status 1 35, 2s + 33 in general), a
runtime or host-layer _exit(1) as 17, a signal death as 19; crash 253 and non-halt 251
are unchanged. Reruns under the new map: verification/unikernel-fault-qemu.txt (and the
corpus rerun in verification/unikernel-corpus-qemu.txt).

Every boot is an EMULATED BOOT under QEMU 11.1.2 with TCG (-accel tcg), machine type the
qemu-system-x86_64 default (pc), -cpu max, -m 1024, -no-reboot, the exit device
-device isa-debug-exit,iobase=0xf4,iosize=0x04 (QEMU 1 = status 0, 3 = status 1),
-append "+RTS --threads 1 --gpu off", timeout 120 s, and two serial ports:
-serial mon:stdio (COM1, the console) -serial unix:<sock>,server=on,wait=off (COM2, the
Writ channel). One lane, CPU only; not native, not GPU. Unikraft 0.21.0 (7351f8b),
kraft 0.12.16, lib-musl, gcc 16.2.1; Bend 2.0.39 (BEND_NO_TELEMETRY=1). W is the build
workspace, realpath ../writ-unikernel. Nothing built is in the tree.

== Result ==

Two runs, each one boot of the monitor image driven by the host-side client probe through
check-channel.sh, both PASS (client output, console, and QEMU status equal to the
references; exit 0):
  accepted: R's report-to-summary request -> Committed, reason 0 (session_revision 7,
            reader_balance 45, descriptor 2, frontend_revision 2), then a frame with
            length 65 -> host.c's transport refusal (kind 3, decision 3, reason 256, before
            Bend), version 2 -> Denied 1, S's session named by the body -> Denied 6, the
            first request replayed -> Denied 6 (the session is Committed); fuel exhausted,
            QEMU 1.
  denied:   S's session named by the body under subject R first -> Denied 6 by
            DataOS.commit_from_capability (descriptor 2 bound), refusal, Denied 1, R's
            request -> Committed 0, replay -> Denied 6; QEMU 1.
Every reply record equals, byte for byte, the reply MonitorCheck.bend computes on Linux for
the same Bend records in the same order (both runs; "Cross-check" below). The reason-5
contrast (S as the subject: Denied at the descriptor, nothing bound) is shown on Linux by
MonitorCheck.bend, since the image's subject is fixed to R. A negative control (the
denied order checked against the accepted references) FAILs and exits 1. check-binary.sh
on the monitor ELF: effect rows exactly Unikraft.log, Unikraft.put, Unikraft.take, exit 1
(outside the monitor profile, allow lists unchanged). No RPC surface: the only interface is
the fixed 80-byte frames on COM2.

SUBJECT. There is no parent route on a unikernel. The route subject word is a build-time
constant (WRIT_CHANNEL_SUBJECT=1 -> -DWRIT_UK_CHANNEL_SUBJECT=1u for host.c), handed to
Bend by writ_uk_take_poll beside every record and never read from the body (the body's
claimed_subject 2 in the "other" record is logged as untrusted and not used). This is
SCAFFOLDING for the ingress twin: whoever builds the image chooses the word, and whoever
reaches the socket speaks as it. It is the gap UL-008's single-ingress rule and the
appliance host must close.

TRANSPORT. COM2 (0x2f8, CONFIG_LIBNS16550_COM2=y): drivers/ukconsole/ns16550/com.c
registers it with flags 0 (com_init_port), so console output never goes to it; host.c
reads and writes it with uk_console_in_direct/uk_console_out_direct
(lib/ukconsole/include/uk/console.h:86, :99). Unikraft.take parks with
io_wait_on(w, 0, 0, io_until(ms), more) and polls COM2 on each wake (Task 2: ms = 10;
fix round 1: 10 idle, 1 while a frame is partly in): there is no COM2
descriptor to park on (lib/posix-tty/serial.c reads every STDIN console and reports POLLIN
statically) and com_setup leaves COM2's interrupts off. No io_work (its helper thread
outlives main here: verification/unikernel-effects-qemu.txt R0-E1), no loop-thread block.
Wall time per boot 4.3 to 4.4 s in the Task 2 runs. CORRECTED in fix round 1: that time
was not spent before the first take (a boot with no second port reaches its first take
and exits at 0.3 s). With COM2's FIFOs off the port holds one byte, so each 10 ms wake
collected about one byte, about 0.8 s per 80-byte frame; measured 0.86 s for one accept
round trip. Fix round 1 polls at 1 ms while a frame is partly in: 0.14 to 0.56 s per
round trip, 0.8 to 1.8 s per boot ("Fix round 1" below).

  - app/Kraftfile: CONFIG_LIBNS16550_COM2: 'y'. Reason: registers QEMU's second serial port
    as the console device "COM2" (flags 0, not a console or stdout device) for host.c. It
    is in every image built from the template; images whose program uses no Unikraft
    channel effect are unaffected (checked: hello and the Task 1 probe rebuilt in a fresh
    set $W/effects2 with the new template; hello: console "hi", QEMU 1, check-image PASS, no
    writ_uk symbol; probe: delta_ms=102, QEMU 1, check-image PASS).
  - app/Makefile.uk: WRIT_CHANNEL_SUBJECT (nonzero decimal word, else $(error)) becomes
    APPWRITBEND_CFLAGS -DWRIT_UK_CHANNEL_SUBJECT=<word>u. Reason: the build-time subject.
  - scripts/build.sh exports WRIT_CHANNEL_SUBJECT (default unset).
  - scripts/run.sh: WRIT_QEMU_SERIAL2 adds -serial mon:stdio -serial <spec> (with
    -nographic and no -serial, QEMU's default is mon:stdio, so COM1 is unchanged).
  - scripts/check-channel.sh: new (one channel run, exits 1 on a changed outcome).
  - host.c now refuses to build without CONFIG_LIBNS16550_COM2.
