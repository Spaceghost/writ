Unikraft effect-twins lane, Task 3 (change task 2.3): the runtime's fault message, the
exit-code map moved off QEMU 1, and arena exhaustion
Recorded 2026-11-04 on Linux x86_64 (Manjaro, kernel 7.2.9), no root.

Every run below is an EMULATED BOOT under QEMU 11.1.2 with TCG (-accel tcg), machine pc,
-cpu max, -no-reboot, the isa-debug-exit device at 0xf4, +RTS --threads 1 --gpu off,
through hosts/unikraft/scripts/run.sh; -m as stated. Not native, not an accelerated boot,
no GPU. Unikraft 0.21.0 (7351f8b), kraft 0.12.16, Bend 2.0.39 (pins:
verification/unikernel-pins.txt). W = realpath ../writ-unikernel from the repository root;
nothing built is in the tree. The host was heavily loaded (load average about 48); wall
times are indicative only.

== Result ==

1. Fault message. With CONFIG_LIBPOSIX_PROCESS_SIGNAL=y (a trial configuration, not the
   template) the runtime's own handler runs on its alternate stack and the console shows
   "bend: memory fault (machine stack overflow?)"; the image then ends in a Unikraft crash
   ("Cannot deliver SIGSEGV for pf at 0x1080069000", lib/posix-process/signal/deliver.c:428)
   and the hook's crash value, QEMU 253 (two boots, same outcome). With the template
   configuration (no posix signals) there is no message: the guard page fault is a Unikraft
   crash, QEMU 253, as before. The trial needs a build workaround (below) because 0.21.0's
   posix-process does not compile with signals enabled; the template was NOT changed.
2. Exit-code map. Program statuses are written as s + 0x10 (success: QEMU 33), so no
   outcome of the image is QEMU 1, which QEMU itself returns on its own startup errors.
   exit() is told from _exit() by an atexit function in exit_device.c, which gives
   runtime and host-layer stops (_exit(1)) their own value, QEMU 17, apart from
   IO.die(..., 1, ...), QEMU 35.
3. Arena exhaustion: no code of its own, recorded as a limit. Forced with
   scripts/unikernel/Exhaust.bend at -m 1024, 4096, and 12288: every run ends in a Unikraft
   crash, QEMU 253, inside heap_alloc_miss while it writes the free list into a fresh
   arena page, after a time that grows with guest memory (3.3 s, 21.3 s, 111.4 s). The
   guest runs out of memory to back the arena's lazily touched pages before the runtime's
   own bound (corpus_grow failing) is reached, so the runtime's "out of memory" fail-stop
   (err_fail, _exit(1), which would be QEMU 17) never runs, and arena exhaustion shares
   QEMU 253 with the stack-overflow fault.

== Fault message: source (Unikraft 0.21.0, $W/src/unikraft) ==

lib/posix-process/Config.uk:78 LIBPOSIX_PROCESS_SIGNAL, "POSIX signals (EXPERIMENTAL)";
the template Kraftfile does not set it. With it:
  - lib/posix-process/signal/system_error.c:69-72, :99-100: a page fault
    (UK_LCPU_EXCEPT_EVENT_ERR_PAGE_FAULT, handler at UK_PRIO_LATEST) becomes SIGSEGV
    through sys_error_handler_except, unless the fault happened on the auxiliary
    (kernel) stack or before one exists (:41-42), which is then left to the crash path.
  - lib/posix-process/signal/deliver.c:375-429 sys_error_handler: if the signal is
    masked or ignored, or its handler is SIG_DFL, UK_CRASH("Cannot deliver SIGSEGV for pf
    at ...") (:412-428); otherwise the standard delivery path (:422).
  - deliver.c:112-132: delivery uses the process's alternate stack when the action has
    SA_ONSTACK and sigaltstack is enabled (signal/sigaltstack.c).
So SIGSEGV can reach a handler on an alternate stack, which is what Bend's pool_stack
installs: sigaltstack plus sigaction(SIGSEGV and SIGBUS, err_trap, SA_ONSTACK |
SA_NODEFER) (generated C, $W/crash/gen/overflow.c:1940-1953). err_trap (:549-555) writes
the message to fd 2, sets SIG_DFL, and re-raises. Without LIBPOSIX_PROCESS_SIGNAL nothing
turns the page fault into a signal and the crash screen is all there is (matrix E4).

Observed sequence with signals (read from the console; not traced): the message, then
"Cannot deliver SIGSEGV for pf at 0x1080069000" and the crash screen, crash rip in
sys_error_handler at deliver.c:428 (addr2line on the .dbg). Read as: err_trap's re-raise
did not end the process, the handler returned, the faulting access ran again, and the
second fault found SIG_DFL, so posix-process crashed instead of delivering it. The image
does not resume after the fault either way; the hook's crash value is written.

Build workaround for the trial (no source patched): with LIBPOSIX_PROCESS_SIGNAL=y the
build stops at lib/posix-process/shutdown.c:63, "implicit declaration of function
'pprocess_signal_send'": shutdown.c includes "signal/signal.h" before <uk/config.h>, so
that header's "#if CONFIG_LIBPOSIX_PROCESS_MULTITHREADING" (signal.h:116) reads 0 and
the declaration (signal.h:287) is skipped. The trial adds "-include uk/config.h" to
UK_CFLAGS. Scratch script $W/fault/build-sig.sh (fb8ed4a8...): build.sh's steps for set
"fault" with that flag; the scratch Kraftfile $W/fault-unikraft/Kraftfile is the template
plus CONFIG_LIBPOSIX_PROCESS_SIGNAL: 'y'.

== Exit-code map (hosts/unikraft/exit_device.c) ==

| How the image ends | Value | QEMU (2v + 1) |
| --- | --- | --- |
| program status s, 0 <= s <= 108: main returned s, or exit(s) | s + 0x10 | 2s + 33 |
| program status above 108 (clamp) | 0x7f | 255 |
| status 1 without exit(): runtime or host-layer stop (_exit(1)) | 0x08 | 17 |
| other nonzero status without exit(): ended by a signal | 0x09 | 19 |
| shutdown target not a halt | 0x7d | 251 |
| crash (UK_CRASH_EVENT) | 0x7e | 253 |
Values 0x00 to 0x07 and 0x0a to 0x0f are never written, so QEMU 1 (QEMU's own startup
failure), 0, and 124 (timeout) are never an outcome of the image. timeout(1)'s 125 and
127 equal QEMU for program statuses 46 and 47.

Why the exit()/_exit() distinction is needed (generated C of Bend 2.0.39, cited from
$W/crash/gen/overflow.c; the runtime part is the same in every program built here):
  :538-542  err_fail: fflush, the message to stderr, _exit(1); every runtime fail-stop
  :545      err_post on the host = err_fail(ERR_TEXT[code])
  :520      ERR_TEXT[3] "out of memory: run again with a bigger span, as in +RTS --gpu 8GB"
  :728-731  heap_alloc_miss: err_post(H, ERR_HEAP) when the arena cannot grow (corpus_grow)
  :3183-3187 CID_Halt / CID_Exit (IO.die, IO.exit): io_sync(), then exit(status)
  main returns 0 after a normal run.
posix-process stores the status of exit_group either way (lib/posix-process/exit.c:203,
:262-269), so the term context's exit_code is 1 for both IO.die(1) and err_fail; the
message goes to stderr, which the hook does not read. musl's exit() runs the atexit
functions and _exit() does not, so exit_device.c registers writ_exit_mark with atexit
from an application constructor (lib/ukboot/boot.c do_main runs __init_array right
before main) and the term function reads whether it ran. A signal death stores the signal
number (exit.c:205; deliver.c:44-55), and an init process still running at shutdown
without signals gets 0x80 | SIGKILL (shutdown.c:101): both are "nonzero without exit()".
Limits: every runtime and host-layer stop shares 17 (the runtime's out-of-memory stop, if
it were ever reached here, would not be told from a failed reservation; forced arena
exhaustion is a crash, 253, below); main returning 1 on a bad
+RTS argument also counts as a runtime stop; if atexit failed, exit(s != 0) would be
misnamed as 17 or 19, never as success.

== Arena exhaustion (scripts/unikernel/Exhaust.bend) ==

fill(4000000000n, []) builds a 4e9-cell list in an accumulator and sum walks it only
afterwards, so all cells are live at once. The prediction from the generated C was the
runtime's "out of memory" fail-stop (err_fail, _exit(1), QEMU 17 under the new map).
$ hosts/unikraft/scripts/run.sh codesa ex1 exhaust "+RTS --threads 1 --gpu off" 300 1024
exhaust probe start
[    3.344375] CRIT: Unikraft Crash - Ijiraq (0.21.0~7351f8b)
[    3.346136] CRIT:  rip: 0008:00000000001c1f0d
[    3.346515] CRIT:  rax: 000000000b071200 rbx: 0000000007f69080 rcx:0000000000000001
253   (wall 3.5 s)
  ex2, -m 4096:  crash at 21.259 s, same rip, rbx 000000001fe9f080; 253 (wall 21.7 s)
  ex3, -m 12288: crash at 111.367 s, same rip, rbx 000000005fc86080; 253 (wall 112.6 s)
addr2line on exhaust-qemu.dbg: rip 0x1c1f0d is heap_alloc_miss, app.c:731, the loop
"H[got + ((u64)(i - 1) << cls)] = ..." that threads a fresh page's cells into the free
list (exhaust.c:730-732), i.e. the first write to a new arena page. The crash time grows
with -m; rbx at the crash grows with -m too (read as the arena position; not traced), and
in the 12 GiB run it is past the initial 8 GiB reservation, so corpus_grow had already
grown the arena once. Read: the arena's pages are reserved lazily and backed on first
touch; once the guest has no memory left to back one, the fault is a Unikraft crash, not
a runtime fail-stop, at every size tried. The runtime's own bound (corpus_grow failing at
2^43 bytes or on a failed fixed-address map) was never reached. Limit, recorded: on this
kernel arena exhaustion has no code of its own and is not told apart from the stack
overflow (both QEMU 253); the "out of memory" message never appears. With posix signals
enabled the same fault would presumably reach err_trap and print the memory-fault message
(not run).
