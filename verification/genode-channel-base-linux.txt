DESIGN POINTS CHECKED IN THE GENODE SOURCE
  - Libc keeps the main entrypoint busy while the Bend main is suspended:
    Libc::Kernel::run loops on _env.ep().wait_and_dispatch_one_io_signal()
    while the application is suspended
    (repos/libports/src/lib/libc/internal/kernel.h:460-533), and that call
    defers non-I/O signals and serves no RPCs
    (repos/base/src/lib/base/entrypoint.cc:145-199). Session requests reach
    a component through base's Root_proxy on its own "root" entrypoint
    (repos/base/src/lib/base/root_proxy.cc:110-150), which then calls the
    announced root by RPC. The shim therefore serves the Writ_channel root
    and every channel (RPCs and the request Signal_handler) on a dedicated
    Genode::Entrypoint "writ_channel" (repos/base/include/base/
    entrypoint.h:135). Not tried on the main entrypoint (it would not be
    dispatched while Bend waits).
  - Server side: Root_component<Channel> (repos/base/include/root/
    component.h:100-340, _create_session/_destroy_session), session objects
    as Rpc_object<Writ_channel::Session>, modelled on Report::Session
    (repos/os/include/report_session/report_session.h, client.h,
    connection.h) and repos/os/src/server/terminal_log/main.cc (root +
    announce). Buckets: Attached_ram_dataspace (repos/base/include/base/
    attached_ram_dataspace.h:112). Signals: Signal_handler on the channel
    entrypoint (its capability is what request_sigh returns) and
    Signal_transmitter to the client's registered context (base/signal.h).
  - Labels: the parent prefixes every session label with the requesting
    child's name (repos/base/src/lib/base/child.cc:152-155), so the server
    sees "writ_client_r -> channel" and the client cannot change the
    prefix. Policy matching: os/session_policy.h with_matching_policy
    (repos/os/include/os/session_policy.h:36-200; label, label_prefix,
    label_suffix scoring, falls back to <default-policy>, which the shim
    refuses). Run-config syntax for policy labels: repos/gems/run/
    depot_deploy.run:96; routes to a child: repos/os/run/ahci_block.run:54.
  - Wakeup: writ_shim_take blocks in Genode::Semaphore::down
    (repos/base/include/base/semaphore.h) on the Bend runtime's io_work
    helper thread; the request Signal_handler ups it. The loop itself is
    woken by the runtime's own completion pipe (io_take reading io_wake_fd,
    monitor.c, over the component's vfs_pipe /pipe), the libc wakeup the
    event loop already uses. This is the "condition the signal handler
    signals" option; a second libc pipe written from the channel
    entrypoint was not used (that entrypoint is not a libc context).

BEND RECORDS AND TWINS
  Genode.bend adds type Request (18 U32 fields: channel, subject, then the
  16 record words) and type Reply (16 U32 fields), and the effect defs
  Genode.take() -> IO(Request) and Genode.put(channel: U32, reply: Reply)
  -> IO(Unit). In monitor.c the constructors have arity 18 and 16 and are
  not hot (CID_T entries {18,0,0} and {16,0,0}); the compiler stores U32
  fields as raw words at the node's location in declaration order (e.g. a
  Reply built with heap_alloc(e, cls_fit(16)) and e.mem[l + i] = field i).
  genode_take.c packs a Request the same way (io_seal per field, a no-op
  for a cold constructor); genode_put.c reads the Reply with ctr_take and
  frees it with spare_free, as io_cbuf reads a String cell. Twins:
    io_eff(CID____effects_Genode_Genode_take, genode_take_run);
    io_eff(CID____effects_Genode_Genode_put, genode_put_run);
  named genode_<x>_run so scripts/runtime-profile/check-binary.sh maps them
  to Genode.take / Genode.put (the check itself is Task 3).
