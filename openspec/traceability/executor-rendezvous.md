# Executor rendezvous traceability

Baseline contract: [executor-rendezvous](../specs/executor-rendezvous/spec.md); the original
change is [archived](../changes/archive/2026-11-05-add-executor-rendezvous/).
Nothing here marks a host adapter, a facade entry
point or an acceptance scenario as implemented: the rendezvous model exists in
Bend only, it is not wired to any host, the DataOS facade has no rendezvous
entry, and the path stays disabled until its host preconditions hold. Every
`from: I.Principal`, issuer state, transfer context, `now`, Negotiation
session and context, HostPrimitives state and worker session id in the tests
is a synthetic fixture standing in for a trusted host input;
[docs/EXECUTOR-RENDEZVOUS.md](../../docs/EXECUTOR-RENDEZVOUS.md) lists each one,
who must supply it, and what goes wrong if it is wrong.

Implementation: [Rendezvous.bend](../../Rendezvous.bend) (public entry points
`open` (against the monitor's index of opened requests, `AlreadyOpen`), `submit_offer`, `submit_approval`, `withdraw_approval`, `select`,
`abandon`, `withdraw_offer`, `submit_evidence`, `dispatch`, the projections
`negotiation_context`, `commit_context` and `provider_registry`, the read-only diagnostic
`ineligibility`, and `valid`). Use-time checks, unchanged:
[Negotiation.bend](../../Negotiation.bend) (`challenge`, `sample`, `approve`,
`reserve`, `start`), [Backplane.bend](../../Backplane.bend) (`commit`),
[DataOS.bend](../../DataOS.bend) (`commit_from_capability`),
[Frontend.bend](../../Frontend.bend) (`mount`, `open`, `checked_plan`) and
[HostPrimitives.bend](../../HostPrimitives.bend) (`issue`, `admit_worker`).
Authority source: [Issuance.bend](../../Issuance.bend) (`current`, `registry`).
Executable cases: [RendezvousTests.bend](../../RendezvousTests.bend), run by
`bend Tests.bend`, with the recorded run in
[verification/executor-rendezvous.txt](../../verification/executor-rendezvous.txt):
229 Rendezvous checks, 1657 in the corpus on this lane's tree (1428 at master
78449c9 plus 229). The counts are recorded, not pinned; the controller
re-pins them after the parallel lanes merge. Laws:

## Model details

Every accepting transition advances the revision exactly once, and every
denial returns the supplied state with one closed-set reason. An offer's
provider and an approval's issuer are claims compared with the authenticated
`from`; a provider's authority is only a registered Issuance grant that is
`I.current` at the call, whose subject is the provider and whose plan is the
request's plan. Nothing in `Rendezvous.bend` constructs or edits a
`T.Plan`, produces a `WriteIntent`, or calls Backplane or the DataOS facade.

The HostPrimitives leg is driven, not reviewed-only. The plan ruling asked
whether a worker session whose caller subject is the provider could be bound
without editing the `HostPrimitivesTests` fixtures. It can: the session is
bound through the public `HP.open_session` from synthetic session evidence in
`RendezvousTests.bend` (the `host()` fixture of section `dispatch`), and the
target report and route inventory are HostPrimitivesTests' unedited
`full_report()` and `mediated_inventory()`. The current-authority scenario
then opens A's input from `provider_registry` (`F.mount`, `F.open`), issues
it on A's worker session (`HP.issue`) and admits the worker
(`HP.admit_worker`, one `DeliverInputs` effect for that input); the
dispatch-to-commit revocation scenario shows `HP.issue` finding no handle
once the projection is empty. The commit is then judged on `commit_context`,
which names that dispatch and worker session. This is the Bend model only: no native host
confines the worker, and the adapter that admits workers only from
`provider_registry` after a recorded dispatch is a host precondition.

## Cross-cutting reviewed-only gaps

- Per-use projection rebuilding: the host must rebuild
  `negotiation_context`, `commit_context` and `provider_registry` from the current
  rendezvous, issuer and transfer states for every use. The tests rebuild at
  each step themselves; no host does.
- One rendezvous per request: the host opens every rendezvous through `open`
  on its durable index of opened requests, installs the returned index, never
  removes an entry or builds a state with `fresh`, and never presents one
  session's challenge or sample to two rendezvous (ER-005, ER-001).
- The current host state at the commit: the host names its current
  HostPrimitives revision to `commit_context`, as to `dispatch`; a
  pre-restart state named at its own old revision is not detected.
- `select` and `abandon` are invoked only by the monitor.
- Host serialization of installs: the host must install an accepted state
  atomically at `expected_revision` and serialize transitions. Races are
  modeled by the revision check only.
- Worker session identity supplied by the adapter: a HostIdentity session's
  `F.Caller` is trusted to come from authenticated native evidence.
- Grants installed by the monitor: `Snapshot.issuer` is the current
  Issuance state the monitor supplies; Bend cannot detect a stale one.
- Unmetered trial compute: add-metered-sample-execution is not implemented.
- The quote is a ceiling, pending Spaceghost (q18); settlement is out of
  scope.
- Host wiring: no host adapter, transport, durable state or facade entry
  exists, and the path stays disabled.
- The worker that produced the committed output: `commit_context` binds the commit to the dispatch record and the reported worker session, but the host attests that the reported worker is the one that ran (see ER-001), and must pass `commit_context`, rebuilt, to every commit. The host passes the same Negotiation session to `commit_context` and to the commit; Bend cannot tie them, because the commit takes its session separately.
- No Lean verdict: the laws are checked by ordinary `bend PROOF.bend` only.

Not exercised anywhere in this change: transport authentication, signature
verification for offers and approvals carried off-host, durable storage and
recovery, concurrent hosts, trial metering, quote settlement, and any native
host (Genode, Unikraft, Linux, Windows, rclone). A CPU run is not a GPU test.

## Shared approval and selection identifier exhaustion

The pinned Nat runtime supports values through 2^48 − 1. The shared `next_id`
must remain above every allocated approval and selection ID, so max − 1 is
the last allocatable ID. Approval submission and selection append
`IdExhausted` as the final gate, preserving prior failure precedence and
unchanged denial; the constructor extends the public model error API. Refusing
an unrepresentable successor preserves monotonic IDs rather than weakening a
security law. The [boundary tests](../../RendezvousBoundaryTests.bend) check
both final allocations and exhausted/stale/multiple-fault denials with full
state comparison, plus offer submission, withdrawal, current selection and
abandonment at terminal `next_id`. Revision exhaustion is separate and remains
unresolved; no authenticated host or durable serialization is established.
