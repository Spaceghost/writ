# Same-worker pre-admission feasibility: source review only

A strict LPAC worker currently reaches `WSAStartup` and the USER32/OLE32 checks only after it has been admitted and has read the public canary. A proposed pre-admission phase could capture initialization status in that **same retained process**, but it would change the probe protocol, scheduling and process state. The source review below does not establish a safe handoff, a restriction-preserving initialization fix, or a confinement result. It authorizes no implementation or native run.

## Existing sequence and constraints

1. `writfs.c` freezes the public fixture and starts the Bend policy process, builds positive loopback receivers, and creates one anonymous report pipe plus two auto-reset events. Its worker command includes mount path, public fixture digest/size, those handle values, broker PID, a public external path and four ports. This is a public canary, but it is not the proposed no-data command. `writ_worker_create` passes exactly those three inherited handles, starts the held probe image suspended, and configures the strict zero-capability LPAC token, child restriction, Win32k disable, job/UI controls and four owned WFP filters. There is no separate preflight input channel or post-launch delivery of the mount parameters.
2. The broker closes its report writer, starts the WinFsp dispatcher/mount and verifies an ordinary reader is denied before `ADMIT`. It then sends `ADMIT` to Bend for actor slot 1, checks a wrong process carrying the worker token is denied, and resumes the retained worker. `native_actor` uses WinFsp request PID/token and `writ_worker_matches`; that matches retained PID and creation time/liveness, user SID and authentication LUID, plus LPAC token facts. PID or package SID alone is insufficient. Bend remains the decision authority; native identity is evidence, not authority.
3. The worker parses its command, opens and reads the mounted canary, then performs network and channel probes. `report_to_broker` writes a `WRIT_PROBE_REPORT`, signals `ready` and waits on `proceed`. `read_report` waits on either `ready` or the worker process, checks that `PeekNamedPipe` currently reports exactly one struct, reads it, and validates magic, phase and expected passed/failed masks. It is a three-phase protocol, not an authenticated general-purpose input protocol or a proof of future pipe EOF; do not silently repurpose phase numbers or claim that an event alone binds the sender. Phase 2 retests network after owned WFP removal; phase 3 tests revocation and the retained open. Final success requires the actual worker's confinement, the independent no-data diagnostic, revocation and cleanup.
4. `writ_worker_resume` currently accepts any `ResumeThread` result other than `(DWORD)-1`; it does not establish previous suspend count exactly 1. Existing WFP/session and worker cleanup paths include operations whose individual success is not all independently read back. A new feasibility design cannot describe those checks as already provided. Fixing or extending them is separate implementation work and must preserve failures and existing gate semantics.

## Candidate transition, conditional on unresolved controls

One candidate would launch the **same fixed worker executable and same retained process**, initially with no mount path, fixture digest/bytes, Writ data handle or policy pipe, while keeping the actor unadmitted. It would run only a bounded initializer/report phase, wait at a well-defined transition, and receive the public-canary phase parameters only after the broker validates required controls and Bend admission. However, the current command-line and three-handle contract cannot deliver these later parameters: the existing `proceed` event conveys no data, and the report pipe is child-to-broker only. Adding a broker-to-worker channel, reusing a phase channel, or allowing a shared object each introduces a reachable input or output and needs an exact owned-object, framing, identity and information-flow design; none is currently selected. Passing mount parameters at creation avoids that new input channel but fails the stronger proposed no-data-path condition and must not be described as satisfying it. A second worker or a relaxed helper cannot stand in for the actual worker.

The report writer, both events, initialized DLL/provider state, any new handles or memory state and potentially shared OS/profile state can survive into the later worker phase. The existing report pipe must remain reachable to carry the three actual worker phases unless the protocol is redesigned. Consequently, merely closing a new preflight channel is insufficient. Every surviving pipe/event/state route must be either retired and independently verified absent before admission, **or** explicitly mediated and bounded under the existing information-flow/commit rules, with no unapproved peer. Numeric completion fields, status codes, timing and logs can also convey information; a finite report format alone is not a proof that a compromised writer cannot leak. At transition revalidate the retained actual worker lifetime, token, job, mitigation, image, reachable handles, monitor/session/authority, WFP and any relevant label/capability/budget/epoch/scope obligations. Account for races between readback and admission/commit, failure, revocation and concurrent requests. If any required condition is unknown, stop before protected input and do not award credit.

A suspended initial child gave the earlier PSS feasibility runs a bounded snapshot, not a continuing guarantee. Microsoft documents [handle-list launch inputs](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute), [PSS capture](https://learn.microsoft.com/en-us/windows/win32/api/processsnapshot/nf-processsnapshot-psscapturesnapshot) and [capture flags](https://learn.microsoft.com/en-us/windows/win32/api/processsnapshot/ne-processsnapshot-pss_capture_flags), but these citations do not establish a race-free, complete, independently authenticated handle and mutable-state view for a running process at admission. Microsoft warns [SuspendThread](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-suspendthread) is not intended for application synchronization and can deadlock; suspending the original thread alone does not show that every other thread or peer is quiescent. The existing process-child restriction is not a ban on threads. A successful earlier PSS walk cannot prove handles or alternate paths are absent after initialization. A supported bounded and race-safe transition mechanism, including independently identified target/peer lifetimes and access rights, remains an explicit unresolved prerequisite.

## What a separate design must settle

- Specify exact preflight and later messages, owned endpoints, deadlines, malformed/duplicate/truncated/replayed/out-of-order behavior, all surviving channels, cleanup and how no pre-admission protected data or caller-controlled authority enters. Bind every observation and reply to the same held process lifetime and authenticated broker; no PID-only or bearer-only authority.
- Establish a reviewed, supported method for transition-time lifetime and control revalidation plus concurrency/handle and mutable-state safety, or explicitly leave the candidate infeasible. A worker's self-report, launch allowlist or instantaneous PSS result alone does not establish that property.
- Describe how Bend admission/revocation and open handles remain authoritative, including denied pre-admission `STAT`/`OPEN`, stale epoch/capability/budget/scope rechecks, crash/timeout and repeated transition attempts. Do not create a second release route or clear policy state.
- Preserve the original ordered real-worker effect probes and their functioning positive controls. Preflight may perturb loader state, Winsock state, handles, cache, timers or OS state; compare and retain those differences instead of calling the later observation identical. A successful initializer is not an access-denied result. No initializer result from another process, generic error, static filter readback or mitigation bit earns byte-worker confinement credit.
- Add meaningful synthetic protocol, lifetime, race/failure-classification and cleanup tests, then separately reviewed native acceptance on the real worker. Require strict profile and no weaker fallback throughout; missing setup or unverified cleanup remains incomplete. Do not add or alter policy logic in C.

Until those issues are resolved, the present repository supports the prior strict run's **incomplete** classification and the separate no-data observations, but not a safe same-worker pre-admission implementation or a corrected strict gate. The applicable contracts include NM008 in `openspec/specs/native-host-canary-mounts/spec.md`, WH-002/003/004/007/009 in `openspec/changes/add-windows-host/specs/windows-host/spec.md`, and the root authority and commit invariants.
