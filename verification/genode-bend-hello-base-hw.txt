SHIM CHANGE (hosts/genode/shim/writ_mem.cc; one C++ unit, GB-006)
  Selection: build time. hosts/genode/shim/writ_shim.mk (new build file,
  included by writ_bend.inc and by the reservation probe's target.mk) adds
  -DWRIT_SHIM_FAULT_LINUX_SIGSEGV for KERNEL=linux and
  -DWRIT_SHIM_FAULT_REGION_MAP for KERNEL=hw to CC_CXX_OPT (C++ only; the
  generated C's compile line is unchanged), and stops the build for any other
  kernel; writ_mem.cc has an #error unless exactly one is defined. Recorded
  per build dir: build/x86_64 (KERNEL ?= linux) -> WRIT_SHIM_FAULT_LINUX_SIGSEGV;
  build/x86_64-hw (KERNEL ?= hw) -> WRIT_SHIM_FAULT_REGION_MAP. Why not a
  config attribute: E2 shows the wrong front end is a fatal exception, so a
  binary must not carry it, and the integrator must not choose it.
  Shared: _resolve_fault (guard check, populated check, _populate with its
  RAM/cap margins, the faults-resolved counter), used by both front ends.
  base-hw front end (case 2 of the header's "Fault delivery"):
    - "writ_fault" Genode::Entrypoint (stack 64 KiB), started in
      Libc::Component::construct before main (outside libc's context, as the
      channel's entrypoint), with one Signal_handler (Rm_fault_handler).
      Added rather than reusing "writ_channel": that entrypoint exists only
      with a <writ_channel> node, and a fault must not queue behind session
      requests or client signals. Its thread touches only the chunk tables.
    - _reserve registers that handler on each new reservation's region map
      (Region_map_client::fault_handler, repos/base/include/region_map/
      region_map.h:79-87, client.h:46) before returning the reservation.
    - The handler takes the shim mutex and, for every live reservation,
      calls Region_map_client::fault() (client.h:47; Fault/Type,
      region_map.h:38-44; the address is relative to the region map) until
      Type::NONE, resolving each fault through _resolve_fault. The
      populating attach wakes the faulter (repos/base/src/core/
      region_map_component.cc:272-278, Rm_faulter::
      continue_after_resolved_fault -> Pager_object::wake_up,
      repos/base-hw/src/core/pager.cc:68-72). Signals coalesce, hence the
      drain. Core's side: a fault with no region in the reservation's
      region map is reflected to the registered handler
      (region_map_component.h:427-440) and the faulter is halted
      (region_map_component.cc:63-113, pager.cc:145-148).
    - Refusal: log "writ_mem: unresolved fault at <addr> (<why>), component
      terminates" through the LOG session, leave the faulter halted (never
      resumed), Parent::exit(139). Without a registered handler core would
      instead log "illegal <fault> by pager_object: ..." and halt the thread
      (region_map_component.cc:102-104), with no exit and so no record by
      init. In b123e10/4f7c0e3 the handler was registered only on each
      reservation's region map, so that was still the outcome for a fault
      outside every reservation; fix round 1 also registers it on the PD's
      address space, stack area, and linker area (FIX ROUND 1).
    - Retry table: not used on base-hw (header, "Retry table"): core
      resolves touches of attached ranges itself, so a reflected fault on a
      populated chunk is refused. "benign retries" stays 0.
  base-linux front end: unchanged in behaviour; its decision now goes
  through _resolve_fault (same order: outside, guard, populated -> retry
  table, populate). The Linux ABI pieces, the retry table, and _lookup are
  compiled only with WRIT_SHIM_FAULT_LINUX_SIGSEGV. Implementation tokens
  of the base-linux path therefore changed (a refactor, not comments only),
  which is why the base-linux runs were repeated (BASE-LINUX RERUNS).
  Console, time, and channel sections: unchanged.
