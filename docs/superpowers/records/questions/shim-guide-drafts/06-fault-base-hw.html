Shim review 6 of 9: the base-hw region-map fault path and exit 139

On base-hw (Genode's own kernel), core is the pager of every thread. When a thread touches part of a region map that has nothing attached, and a fault handler is registered on that region map, core halts the thread and sends a Genode signal instead of logging an error. A Genode Signal_handler is an object bound to an Entrypoint; when its signal arrives, the entrypoint's thread calls the handler method. Signals to one handler coalesce: several faults may arrive as one signal, which is why the handler drains every queued fault. The shim starts its own entrypoint, writ_fault, in construct before main. It registers one handler on every reservation's region map and on the PD's own address space, stack area, and linker area, so that faults outside every reservation (a null pointer, a thread's stack guard) also reach the shim and are refused. Unlike base-linux, a refusal here ends the component by asking the parent: Parent::exit(139), where 139 = 128 + SIGSEGV. See INVENTORY.md:275 (base-hw row) and the six limits at :305-319.

                if (populated)
                    _refuse("populated chunk, fault reflected", r.base + off);
            }

Limit or policy? Two things here look like choices. "Refuse a reflected fault on a populated chunk" (849-850) is not a policy: on base-hw core resolves touches of attached ranges itself, so a reflected fault there is one the shim cannot resolve (143-151). Exit value 139 (300, 794) is a reporting convention. It changes no outcome, since the component ends either way. It matters for evidence, though: init records an exit value, not a fault, and only the shim's own line tells it apart from a voluntary exit 139 (207-211). That is a GB-003 evidence limit, not a GB-006 decision.

Confirm by reading:

  1. A fault in the PD's address space, stack area, or linker area is refused before the shim mutex is taken and is never resolved writ_mem.cc:830-834; the areas are registered once at 884-889.
  2. For each live reservation the handler drains fault() until Type::NONE, sends each fault through the shared _resolve_fault, and refuses (does not retry) a reflected fault on a populated chunk writ_mem.cc:838-852; the base-linux retry table is not compiled here (505-520).
  3. _refuse writ_mem.cc:788-796 logs the counters line and the reason through the LOG session, calls Parent::exit(REFUSED_FAULT_EXIT), and sleeps; it never wakes the faulting thread.
  4. No reservation can exist without the handler: writ_fault is started in construct (1902-1905, 863-891), each new region map registers the handler before _reserve returns (967, 895-898), and _reserve refuses if the handler was never installed (946).
