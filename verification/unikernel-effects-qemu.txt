readings around Unikraft.sleep(100) differed by 103 ms in one run.sh boot (R1-E2) and by

effect rows, all three outside the monitor profile, exit 1 (R1-E7).

History. R0-E1: the first build ran the sleep on an io_work helper thread and ended with
QEMU 255; that is why helper threads are out on this configuration. R0-E2 to R0-E7: the
second build blocked the event loop's thread in uk_sched_thread_sleep (lib/uksched/sched.c:348;
nanosleep is the same call under CONFIG_HAVE_SCHED, lib/posix-time/time.c:69-97); deltas
100 (R0-E2, run.sh only) and 100, 100, 101 (R0-E3 to R0-E5, check-image.sh). Replaced in fix
round 1 because a blocked loop serves no other computation during the sleep, while the
runtime's time park (`bend guide effects`, "Blocking work leaves the loop in two ways")
waits without a helper thread and keeps the loop live; the review ruled it in.

Not exercised in any round: a second park (re-sleep) and the clock-failure paths of host.c
(no clock fault can be injected without patching Unikraft). A second park is not expected:
the park deadline is io_tick() plus the time left as host.c computed it a moment earlier, and
io_tick reads the same clock (CLOCK_MONOTONIC, lib/posix-time/time.c:223-227 ->
ukplat_monotonic_clock), so the runtime wakes the park only after host.c's deadline has
passed. A clock that stops completely never reaches the deadline; the runtime then never
wakes the twin and the run is bounded only by the harness timeout (60 s, status 124).

Change: Unikraft.sleep parks on the runtime's own timer instead of blocking the loop thread.
unikraft_sleep_run reads the start (writ_uk_clock_ns), sets the deadline start + ms*1e6 ns, and
calls unikraft_sleep_more, which asks writ_uk_sleep_left(start, deadline, &last, round) how
long is left: 0 ends the sleep (Unit); otherwise it returns
io_wait_on(w, 0, 0, io_tick() + left, unikraft_sleep_more), as bend2/effs/sleep.c does for
IO.sleep. No helper thread is created, so the R0-E1 shutdown status cannot arise, and the loop
serves other computations while parked. host.c no longer waits: it keeps the ordered-clock
