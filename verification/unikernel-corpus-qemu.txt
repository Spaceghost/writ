== Harness ==

  hosts/unikraft/scripts/run.sh <set> <n>-m<M> <n> "+RTS --threads 1 --gpu off" <timeout> <M>
which runs
  timeout <T> qemu-system-x86_64 -accel tcg -nographic -m <M> -cpu max -kernel $W/<set>/images/<n>-qemu -append "+RTS --threads 1 --gpu off" -device isa-debug-exit,iobase=0xf4,iosize=0x04 -no-reboot </dev/null; echo $?
(timeouts, as each run-<label>.log's first line records: corpus 3600 s at -m 4096 and
600 s at -m 1024/256/64/32; examples 900 s at -m 4096 and 300 s at -m 1024/256/64; none
was reached) with the serial capture in
$W/<set>/logs/run-<n>-m<M>.raw. Then
  hosts/unikraft/scripts/console.sh $W/<set>/logs/run-<n>-m<M>.raw > console-<n>.txt
  diff console-tests.txt <(sed '1,/^== capture ==$/d' verification/unikernel-corpus-linux-reference.txt)
  diff console-<n>.txt $W/corpus/linux/<n>-1.txt
  grep -cE '^PASS[: ]' console-<n>.txt

Stripped by console.sh, and nothing else (the Linux captures contain no CR, NUL, ESC or
empty line, checked):
  - NUL bytes, CR characters (the serial line ends lines CR LF), and terminal escapes
    matching ESC '[' [0-9;?]* letter and ESC 'c' (SeaBIOS and the console);
  - all bytes before the first 'Booting from ROM' (SeaBIOS, iPXE), that text, and the run of
    two or more dots after it (one example capture at -m 1024 had three dots and a line
    break before the banner);
  - Unikraft's banner, required verbatim as the next 7 lines (the script fails otherwise):
      ^Powered by$
      ^o\.   \.o       _ _               __ _$
      ^Oo   Oo  ___ (_) | __ __  __ _ ' _) :_$
      ^oO   oO ' _ `| | |/ /  _)' _` | |_|  _)$
      ^oOo oOO| | | | |   (| | | (_) |  _) :_$
      ^ OoOoO \._, \._:_:_,\\_\._,  \.__,_:_, \\___)$
      ^ {18}Ijiraq 0\.21\.0~7351f8b$
Every line after the banner is kept. Unikraft printed nothing after the program's last line.

== Limits ==

- Emulated boots (TCG) only; no KVM or Firecracker boot (task 3.1). One CPU, one lane,
  cooperative scheduler; no multi-lane run (task 2.4).
- The corpus's 'Bend parallel producer' checks run on one lane with --gpu off here, as on
  the Linux single-lane reference; no device code ran.
- A matching console and QEMU 1 show the programs' printed outcomes and status; they do
  not exercise the runtime's fault or arena-exhaustion messages (see unikernel-exit-codes.txt
  and unikernel-crash-action.txt).
- Compiler differs from the Linux reference (gcc -std=gnu11 vs clang); outputs still matched.
- Image hashes are not reproducible across clean builds (embedded build time).
