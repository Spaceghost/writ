# Win32k A/C exploratory implementation

The [design](exploratory-win32k-ac-design.md) proposes A/C/C/A fixed no-data LPAC cases with zero capabilities and different Win32k mitigation inputs. The separately reviewed Windows run and exact observations are preserved in [run 42323201217](run-42323201217/README.md). C permits Win32k system calls at the requested mitigation level but has no proven GUI or ambient-resource confinement; the fixed child adds no clipboard, screen/input, window-enumeration, COM-activation or socket/traffic probes. It cannot receive a Writ session, policy, canary, caller-selected data or handles.

The classifier checks the actual full creation-policy input against the exact ON/OFF value, reads the retained child's system-call-disable policy and requires the intended bit plus matching documented other bits. Reserved/unknown bits, unexpected input, unsuccessful readback or any difference in other bits make the sequence incomplete. Both actual child tokens must have zero capabilities; selected other token facts are compared privately. Those fields are not retained in raw form, and the supplied child environment is compared as constructed input but is not independently read from the child. The pre-resume PSS snapshot does not cover later handle state. OS/provider and same-package state, ordering, drift and PSS perturbation can confound any observed pattern; no result demonstrates a causal mechanism, byte-worker confinement or host qualification.

The workflow uses the trusted runner's `RUNNER_TEMP` to locate the fixed child and logs; standalone callers can alter that environment, so the no-data path guarantee is scoped to the controlled workflow. Its exact-ref branch guard and separate job are temporary and must be removed before integration. The fixed ordinary/ACCA/ordinary sequence stops on a failed case, unknown control, timeout or uncertain cleanup. The observer verifies its budget and job membership, the child's membership in its own job and exclusion from the observer job, and the four package WFP filters. Child-exit uncertainty retains shared controls until disposable-VM teardown. Normal cleanup checks session close and the absence of all four owned IDs using a separate engine. No status is available from `CoTaskMemFree`, `FwpmFreeMemory0` or `DeleteProcThreadAttributeList`; native API and failure-path injection remain untested. The strict byte-worker workflow and gate are unchanged.
