## Limits
- One probe program only. No Writ path (Gpu.sweep, Dlm.batch, Transfer.batch) was built or run with the device; nothing here is evidence that those bangs reach bend_dev. Tasks 3 to 7 cover them.
- The validation-run record (`--- record v1 ---`) is defined by Task 2 and is not attached to these runs.
- The observer shows that bend_dev was launched for this process and how many times; it does not check device memory accesses (all kernels are excluded from checking by design), and it does not show which Bend def each lane ran.
- `--gpu on` was the only device mode run. The default (no --gpu, silent CPU fallback when the probe fails), a size such as `--gpu 8GB`, and the failed-probe paths (`err_fail`, the silent `--gpu-build` exit) were read from the driver strings, not exercised; Task 2's negative controls exercise them.
- The silent `--gpu-build` case did not arise: the build wrote bang.gpu, and no run printed the "is missing or stale" note.
- Nsight Systems and Nsight Compute are absent, so no kernel timeline, per-kernel duration or occupancy is recorded.
- The host was loaded (1-minute load average 47.92 to 67.84 in the capture's quoted `uptime` lines, 99.82 at the fix-round rebuild) and the GPU drives the display and serves other clients; wall times and pmon samples are indicative only and are not performance results.
- gdb (the plan's second observer) was not exercised.
- Lean is not on PATH; no proof or --verdict run belongs to this task.
