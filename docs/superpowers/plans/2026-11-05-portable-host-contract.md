# Plan: Portable host contract, section 1 (shared Bend interfaces)

Spec: `openspec/changes/add-portable-host-contract/` (PH-001 to PH-011 in part, tasks 1.1 to 1.4; section 2, host qualification, is a later plan). The gap: the repository has one Genode-shaped binding model (`HostBinding.bend`, GA-001 to GA-011) and one Genode channel record format (`hosts/genode/effects/Channel.md`, a fixed 16-word record read by `hosts/genode/monitor/Monitor.bend`). There is no target-neutral wire schema, no portable identity table with host incarnation, and no Bend definition of the five primitive families (`docs/PLATFORMS.md`, "The shared host contract"). Without them, a Linux, Windows, or Drift-kernel adapter would write its own resolution and publication logic, and nothing would show that two adapters make the same decisions. Section 1 adds the shared Bend layer and the conformance vectors that every adapter must replay. It adds no native adapter, no kernel, no capability issuer, and no sandbox. Native confinement, quiescence, and alias elimination stay host obligations until section 2 supplies evidence.

### Task 1: Versioned references and bounded canonical encoding (tasks.md 1.1)

Requirements: PH-011 "The transport has a bounded canonical schema" (both scenarios: "A peer sends an unknown authority variant", "A peer supplies a complete trusted context"); PH-003 "Native handles remain host-local authority" (the wire part of "A guessed numeric handle": a reference is a name for a monitor table entry, never authority); the wire part of PH-004 "References bind incarnation and generation" (every reference carries both).

Create `HostWire.bend`, importing `Base` only. The header states that decoding produces descriptions, not authority. Public entry points: `encode`, `decode`, `decode_bytes`, `encode_bytes`; the rest are helpers.

- `Ref{host: U32, incarnation: U32, slot: U32, generation: U32}` names one entry of the receiving monitor's identity table (Task 2). The header says it is not a credential and that serialization transfers no native authority.
- `Message`, plan ruling: four tags, with the fixed body widths below. Every field is one U32 word.

| Tag | Message | Body words (after the 3-word header) |
| --- | --- | --- |
| 1 | `Use{ref, operation, rights, claimed_subject}` | 7: ref (4), operation, rights, claimed_subject |
| 2 | `Delegate{ref, rights, lifetime, target_session}` | 7: ref (4), rights, lifetime, target_session |
| 3 | `Complete{ref, sequence, status}` | 6: ref (4), sequence, status |
| 4 | `Release{ref}` | 4: ref |

- Header: word 0 `wire_version()` = 1, word 1 tag, word 2 body length in words. `max_words()` = 10. Byte transports carry each word little-endian. `decode_bytes` takes a `List<U32>` of byte values and is the only byte-to-word step, so a native harness passes raw bytes and interprets nothing. Plan ruling: this is the same byte order and word width as `Channel.md`, so a later migration of the channel changes framing only.
- Bounds, each a named helper: `host`, `incarnation`, `slot`, `generation`, `sequence`, and `target_session` are nonzero. `operation` is one of `operation_read()` 1, `operation_write()` 2, `operation_execute()` 3. `rights` is nonzero and within `rights_mask()` = 7, the read/write/execute bits of the Frontend fixtures. `lifetime` is in 1..`max_lifetime()` (plan ruling: 65535 monitor ticks; it is a relative bound that Task 2 caps by the parent's expiry). `status` is `status_ok()` 1 or `status_failed()` 2. `claimed_subject` may be any value; it is kept so it can be logged as untrusted.
- `WireError` is a closed set: `UnknownVersion`, `UnknownTag`, `BadLength` (empty or short input, header length not equal to the tag's width, actual body count not equal to the header length, byte count not a multiple of 4), `TooLong` (more than `max_words()` words, or more than 4 × `max_words()` bytes), and `OutOfRange` (a field outside its bound, or a byte value above 255). `decode` returns `Decoded{message}` or `Malformed{reason}`. The check order is fixed and documented: length cap, version, tag, header length, body count, field bounds.
- Canonicity: the widths are fixed and there are no optional fields, so every accepted word list is the unique encoding of its message. Tests show `decode(encode(m)) == Decoded{m}` and `encode` of a decoded message equals its input.

`HostWireTests.bend` (registered in `Tests.bend` as `HostWire`) must cover these cases.
- Accepted: each of the four tags, with round trips in both directions; a byte-level round trip.
- Unknown versions: 0, 2, and 0xFFFFFFFF.
- Unknown tags: 0, 5, and 0xFFFFFFFF. Add a tag-5 record shaped like a serialized Context/Ledger/caller (PH-011's second scenario): it is rejected `UnknownTag`, and no record is built from it.
- Malformed lengths: empty input; header only; header length one short and one long for each tag; header correct but body truncated; one trailing word; 11 words; byte input of 3, 5, and 41 bytes.
- Out-of-range values: zero host, incarnation, slot, generation, sequence, and target_session (one check each); operation 0 and 4; rights 0 and 8; lifetime 0 and `max_lifetime()` + 1; status 0 and 3; a byte value of 256.
- Guessed handle: a `Use` naming another session's slot decodes as a description. The check asserts the decoder's output type is `Ref`, with no rights or subject, so authority can come only from Task 2's resolution.

Estimate: about 40 checks; about 200 lines of module and 250 of tests. Create `openspec/traceability/portable-host-contract.md` with a header naming the change, the implementation and test modules, and the rule "model rows only; native evidence is section 2". Add PH-011 and PH-003/PH-004 wire rows with exact check names. Check box 1.1, citing the module and test file.

Acceptance: every listed case is a named check; the suite is green on both backends with PASS count = 782 + this task's checks; `bend PROOF.bend` passes unchanged; OpenSpec strict passes.

### Task 2: Monitor-owned identity, delegation, incarnation, and generation binding (tasks.md 1.2)

Requirements: PH-002 "Subject identity survives the native boundary" ("A client changes its claimed subject", "A delegated endpoint hides its new holder"); PH-003 "Native handles remain host-local authority" ("A guessed numeric handle", "A reference crosses hosts"); PH-004 "References bind incarnation and generation" ("Handle reuse after restart", "Conflicting live mappings"); PH-005 "Delegation cannot widen Writ scope" ("A transferred endpoint requests another bucket", in its delegation part, and "A narrower proxy leaves an old handle alive").

Create `HostIdentity.bend`, importing `Base`, `HostWire`, `Frontend`, and `Transfer`. The header states that every field is monitor state built from authenticated native evidence; `valid` checks structure and does not authenticate.

- `Origin`: `Authenticated{}` | `Inherited{parent_session: Nat}` | `Transferred{from_session: Nat}`. This is how the binding observed the endpoint reaching its holder, a native fact the adapter reports.
- `Session{id, incarnation, caller: F.Caller, origin, delegable: Bool}`. `caller` is set only by `bind_session` from the adapter's authenticated evidence.
- `Entry{slot, generation, holder (session id), owner (Writ subject), handle (Frontend handle id), plan: T.Plan, rights: U32, expires: Nat, parent (0 for a root, else the parent slot), live: Bool}`.
- `State{revision, host, incarnation, next_slot, sessions, entries}`.
- `Error` is a closed set: `ForeignHost`, `StaleIncarnation`, `Forged` (slot 0 or not below `next_slot`), `Retired`, `Ambiguous`, `StaleGeneration`, `NotHolder`, `InheritedEndpoint`, `TransferredEndpoint`, `SubjectChanged`, `NotDelegable`, `WidenedRights`, `WidenedLifetime`, `Expired`, `UnknownSession`, `StaleRevision`. It uses the same `Change` pattern as `HostBinding` (`Accepted{state, issued}` | `Rejected{state, reason}`, with accessors).
- Public transitions: `bind_session`, `mint` (a root entry for a Frontend handle the monitor has already opened; the owner is the session's caller subject), `resolve` (read-only; returns the entry and the session's caller), `delegate`, `retire` (bumps the generation, clears `live`, and cascades to the whole subtree by `parent`, on fuel = `next_slot`), and `restart` (a new incarnation that is strictly greater, with empty sessions and entries and `next_slot` reset to 1).
- Resolution order, fixed and documented, with the first failure reported: host, incarnation, forged, ambiguity (count live entries with the slot: 0 gives `Retired`, more than 1 gives `Ambiguous`, never first-match), generation, holder, session origin, expiry. Plan ruling: an `Inherited` or `Transferred` session can use an entry only through a delegation edge naming that session as holder. Without one, it is denied `InheritedEndpoint` or `TransferredEndpoint` even when it presents a correct reference.
- Delegation, plan rulings. (a) The child copies the parent's plan exactly; `delegate` has no plan parameter, so a changed plan cannot be expressed as an attenuation. (b) The target session's subject must equal the entry owner, or the request is denied `SubjectChanged`. A changed subject needs a fresh `mint` after complete admission and is never a delegation. (c) The parent's session must be `delegable`. Plan ruling: worker sessions in the first topology are created non-delegable, so a worker cannot re-delegate its inputs. (d) Rights must be a subset of the parent's rights, and the child's expiry is at most the parent's (`now + lifetime`, capped).
- `valid`: at most one live entry per slot; every slot is below `next_slot`; every holder is a known session; every session's incarnation equals the state's; every parent link names a lower slot.
- Law, which needs a rationale. `identity_denied_preserves_state`: for every `HostIdentity.State` and `Error`, `Change.state(Rejected{state, reason}) == state`, proved by `{==}`. It fixes the contract every denial path relies on. It does not assert that a transition chose the denial or that the reason is correct; the tests cover that.

`HostIdentityTests.bend` (registered as `HostIdentity`) must cover these cases.
- Accepted: bind, mint, resolve, delegate (narrower rights and shorter lifetime, same plan), retire, restart.
- Forged: slot 0, and slot equal to `next_slot`.
- Ambiguous: a hand-built state with two live entries for one slot. `resolve` denies `Ambiguous`, and `valid` is false.
- Stale generation: after `retire`, the old reference is denied. The new reference resolves; the old one stays denied.
- Stale incarnation: after `restart`, slot 1 is minted again and the prior-incarnation reference with the same slot and generation is denied `StaleIncarnation`.
- Cross-host: a reference with another `host` is denied `ForeignHost`.
- Guessed handle: session B presents A's slot and generation and is denied `NotHolder`.
- Transferred endpoint: a `Transferred` session with no delegation edge is denied; with an edge to it, it resolves.
- Inherited endpoint: an `Inherited` session is denied; with an edge to it, it resolves.
- Claimed subject: a decoded `Use` whose `claimed_subject` is B, presented on A's session, resolves to caller A. A test shows that no transition reads `claimed_subject`.
- Delegation denials: to another subject's session (`SubjectChanged`); wider rights; longer lifetime; from a non-delegable session; from a stale or retired parent.
- Narrower proxy: after delegating a narrower child, the parent still resolves with its full rights and `live` is true, so the old authority is not reported as revoked.
- Retire cascade: retiring the parent makes the child and grandchild stale. Retiring the child leaves the parent live.
- Expiry: a use after `expires` is denied `Expired`.
- Stale revision: each transition with the wrong `expected_revision` is denied.
- Unchanged state: every denial is checked for full state equality with its input, using equality helpers in the test module.

Estimate: about 45 checks; about 350 lines of module and 350 of tests. Add the law to `LAWS.bend` and its `{==}` proof to `PROOF.bend`, importing `HostIdentity`. Add the PH-002 to PH-005 rows. PH-002's "derive the effective subject from trusted session state" is marked model-tested here, and "the adapter establishes the native identity/delegation semantics" is marked as a host obligation for section 2. Check box 1.2.

Acceptance: every case is a named check; all prior checks are unchanged; `bend PROOF.bend` passes with one more law; the suite is green on both backends.

### Task 3: Primitive interfaces, session binding, and worker domains (tasks.md 1.3, first half)

Plan ruling: task 1.3 is split across Tasks 3 and 4 so each fits one dispatch. Task 3 defines the interface types and families 1 and 2. Task 4 adds families 3 to 5 and checks box 1.3.

Requirements: PH-001 "One policy implementation across hosts" ("Native transport accepts a request" in its admission part, and "An adapter offers a fast publication route"); PH-006 "Required confinement precedes plaintext" ("A required kernel feature is missing", "An inherited output remains accessible"); PH-007 "Quotas and observable channels are bounded" ("A worker encodes a secret in diagnostics", "A worker exhausts its resource quota"); PH-014 "Unisolated accelerators cannot access protected state" ("A shared device heap exposes the original graph", "CPU execution satisfies the admitted request"), model part only.

Create `HostPrimitives.bend`, importing `Base`, `HostWire`, `HostIdentity`, `Frontend`, `Transfer`, `Backplane`, and `DataOS`. The header lists the five families, says the target binding supplies only `Fact` values and executes only `Effect` values returned by these transitions, and says that a target-constructed `Effect` is not authorization. That last point is a host obligation, carried to section 2 as reviewed-only.

- Family bits: `family_session()` 1, `family_worker()` 2, `family_artifact()` 4, `family_publication()` 8, `family_revocation()` 16; `all_families()` 31. Control bits: `control_address_isolation()` 1, `control_no_ambient_network()` 2, `control_output_mediation()` 4, `control_quota()` 8, `control_no_inherited_routes()` 16, `control_accelerator_isolation()` 32.
- `Profile{id, required_families: U32, required_controls: U32, backend: Cpu{} | Accelerator{}}` is monitor-owned, taken from the admitted request and never from the target. `TargetReport{supported_families: U32, established_controls: U32}` holds the target's native facts. `RouteFact{kind: U32, mediated: Bool}` is one entry of the worker's complete native inventory.
- `Fact` contains only observations: `SessionEvidence{caller, origin, delegable}`, `Inventory{routes}`, `ResourceRequest{worker, amount}`, `Diagnostic{worker, public: Bool}`, `NativeWriteOffered{worker}`, plus the Task 4 facts. No `Fact` variant carries a decision, a commit result, a plan, or rights.
- `Effect`: `DeliverInputs{worker, slot}` here; Task 4 adds the rest. `Step` is `Done{state, effects: List<Effect>}` | `Denied{state, reason}`. `Error` is a closed set: `Identity{HostIdentity.Error}`, `UnsupportedFamily`, `MissingControl`, `UnmediatedRoute`, `UnisolatedAccelerator`, `QuotaExhausted`, `DiagnosticSink`, `FastPathUnavailable`, `UnknownWorker`, `WrongPhase`, `StaleRevision`.
- `State{revision, identity: HostIdentity.State, workers, ...}`. `Worker{id, session, slot, profile, phase: Prepared | Running | Revoked | Quiesced | Reclaimed, quota_limit: Nat, quota_used: Nat}`.
- Family 1: `open_session` wraps `HostIdentity.bind_session` and requires `family_session()` support. `use` takes a decoded `HostWire.Message` and the transport's session id and resolves through `HostIdentity.resolve` only.
- Family 2: `admit_worker` checks the profile's families against the supported families (`UnsupportedFamily`), its controls against the established controls (`MissingControl`), every inventory route for mediation (`UnmediatedRoute`), and, for an `Accelerator` backend, `control_accelerator_isolation()` (`UnisolatedAccelerator`). Plan ruling: there is no downgrade. An accelerator profile is denied, and an admission for CPU work is a separate request whose profile says `Cpu`. Only then does it emit `DeliverInputs`, so plaintext delivery is the last step of an accepted admission. `charge` denies `QuotaExhausted` beyond `quota_limit` and changes no rights or phase. `diagnostic` denies a public emission from a Running worker (`DiagnosticSink`). Plan ruling: the contract offers no ungated diagnostic route; public output from a protected worker can go only through publication. `native_write_offered` is always denied `FastPathUnavailable` for protected work.
- Laws, which need a rationale. `primitive_denied_preserves_state`: `Step.state(Denied{state, reason}) == state`. `primitive_denied_emits_nothing`: `Step.effects(Denied{state, reason}) == []`. Both are proved by `{==}`. They fix that a denial yields no effect for a target to execute. They do not assert which transitions deny.

`HostPrimitivesTests.bend` (registered as `HostPrimitives`; Task 4 extends it) must cover these cases.
- Accepted: an admission with all controls established; a CPU admission while accelerator isolation is absent, which records backend `Cpu`.
- Missing control: each control bit missing alone. Each is denied, and the effects are empty.
- Target report: a report with fewer families, and a report claiming a lower profile id. Both are denied without changing the monitor profile.
- Inventory: one unmediated route among mediated ones is denied before any `DeliverInputs`.
- Accelerator: the profile without the isolation control is denied.
- Quota: exhaustion is denied, the phase and slot rights are unchanged, and no effect is emitted.
- Diagnostics: a public diagnostic is denied; a non-public diagnostic is accepted with no effect.
- Fast path: a native write offer is denied.
- Session use: `use` with a wire message whose claimed subject differs resolves to the session's caller.
- Unchanged state: full state equality on every denial, plus the stale-revision denials.

Estimate: about 28 checks; about 300 lines of module and 250 of tests. Add both laws and proofs. Add the PH-001, PH-006, PH-007, and PH-014 rows; the native removal or mediation of routes, real quotas, and device isolation are marked as host obligations.

Acceptance: as in Task 2, with two more laws; box 1.3 stays unchecked until Task 4.

### Task 4: Artifact exchange, publication, and revocation families (tasks.md 1.3, second half)

Requirements: PH-001 "One policy implementation across hosts" ("Native transport accepts a request": a failed commit check means no effect); PH-008 "Artifact sealing excludes all writers" ("A read-only mapping retains a writable alias", "A path is retargeted"); PH-009 "Publication observes one current authority boundary" ("Revocation precedes authorization", "Crash recovery repeats a publication attempt"); PH-010 "Revocation includes quiescence and stale completion rejection" ("A device completes after teardown", "A reader already copied plaintext").

Extend `HostPrimitives.bend`.

- Facts: `ArtifactFact{worker, object: Nat, version: Nat, digest: T.CodeId, cpu_writers: Nat, writable_mappings: Nat, device_writers: Nat}`, `QuiescedFact{worker, generation}`, `CompletionFact{session, message}` (a decoded `HostWire.Complete`).
- Effects: `Publish{intent: B.WriteIntent}`, `Reconcile{invocation, digest}`, `StopEffects{worker}`, `Reclaim{worker}`. Plan ruling: there is no recall or erase effect. Revocation stops future effects only, and the module header says it does not erase earlier copies (PH-010's second scenario is reviewed-only beyond that).
- State additions: `sealed` (worker → object, version, digest) and `publications` (invocation → digest), both monitor-owned.
- Family 3: `seal` requires a Running worker and zero writers of all three kinds, or it denies `LiveWriter`. It records the exact object, version, and digest.
- Family 4: `publish(state, expected_revision, worker, current: ArtifactFact, session, expected_session, expected_ledger, ledger, candidate, context: DataOS.Context, expected_frontend)`. It returns `Published{state, commit, effects}` | `Refused{state, session, ledger, reason}`; plan ruling: a separate result type, because publication must also hand back the negotiation session and ledger. The order is fixed. (1) Revision. (2) A sealed record exists (`NotSealed`). (3) `current` equals the sealed object, version, and digest, with zero writers (`Retargeted` or `LiveWriter`). (4) The worker's slot is re-resolved through `HostIdentity.resolve` (`Identity{...}`, so revocation before this point denies). (5) The invocation is not already in `publications` (`Replay`). (6) `DataOS.commit_from_capability` is called with `F.Ref{resolved caller, entry handle}`; `Rejected` gives `CommitRejected` and returns the input session and ledger.
