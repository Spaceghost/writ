How should frontend cleanup survive revision exhaustion?

Josh, should we develop a versioned frontend revision and an authenticated migration design for existing states, or defer this work? We can continue on independent tasks either way.

What we found

The frontend keeps a revision so the monitor can reject stale operations. In synthetic tests, an owner trying to close an open handle at the largest revision the pinned Bend runtime supports caused a numeric-range error on both Bend and generated Node. The same close at the preceding revision succeeded. This requires roughly 281 trillion revision steps from zero; the test supplied a synthetic state directly, not a real native descriptor.

Our current frontend contract promises that an authenticated owner can close its handle even after revocation or expiry. Successful changes advance the revision, and closed handle IDs remain reserved. At the maximum there is no representable next revision. Simply refusing close would leave the handle open; wrapping or reusing a revision would undermine stale-request protection.

A possible direction

We recommend designing a versioned, multiword revision and a monitor-authenticated, atomic migration for already-existing states. The design would preserve open handles and tombstones, fence delayed requests and old snapshots, and retain enough revision capacity for cleanup. It must also handle closing a binding and all of its derived handles as one consistent transition. Reserving cleanup capacity in new states alone cannot repair an existing state already at the maximum; a wider finite counter alone can eventually run out too.

This changes the frontend interface and requires a compatibility and recovery plan: who authenticates and stores the migrated state, how older callers obtain the current revision, and how replay or rollback is prevented. The design record and synthetic results explain the alternatives and remaining checks. The separate handle-ID allocation boundary has been addressed; revision exhaustion and the migration are not implemented.

These results concern the pure model. They do not demonstrate a bypass, actual native cleanup, host confinement, durable recovery, or qualification of any host platform.
