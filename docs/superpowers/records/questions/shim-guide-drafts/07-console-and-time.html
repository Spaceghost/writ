Shim review 7 of 9: Genode.log, Genode.now, Genode.sleep

These three C functions are what the Bend effects Genode.log, Genode.now, and Genode.sleep call (their C twins live in hosts/genode/effects/). Logging uses the component's existing LOG session. Time uses one Timer::Connection, a session to the timer service, opened on first use with the label writ_shim and kept for the component's life. Before opening it, the shim probes the route with Env::try_session, because a plain session request that the parent denies leaves the component hanging silently (header 1185-1190). The claim to check: the Bend program alone decides what is logged and when to wait (1146-1148), and the shim stops the component only when the clock itself cannot be trusted. INVENTORY.md:233-259 ("Timer failure outcomes") and the Timer bullet at :149-161 list this.

Open: writ_mem.cc:1140-1287

Excerpt, writ_mem.cc:1265-1287 (tabs shown as four spaces):

extern "C" void writ_shim_sleep_ms(uint32_t ms)
{
    Timer::Connection *t = _timer_session();
    if (!t || ms == 0) return;
    uint64_t const start    = t->elapsed_ms();
    uint64_t const deadline = start + ms;
    uint64_t       last     = start;
    for (unsigned round = 0;; round++) {
        uint64_t const now = t->elapsed_ms();
        if (now >= deadline) return;
        if (now < start)
            _timer_fail("Timer clock went backwards during a sleep");
        if (round > 0) {
            if (now <= last)
                _timer_fail("Timer clock did not advance across msleep");
            _timer_short_wakes++;  /* msleep returned before the deadline */
        }
        if (round == MAX_SLEEP_ROUNDS)
            _timer_fail("sleep exceeded MAX_SLEEP_ROUNDS msleep calls");
        last = now;
        t->msleep(deadline - now);
    }
}

Limit or policy? The exits here (1245, 1247, 1276, 1279, 1283, all through _timer_fail at 1211-1216) are fail-stop host-failure handling. A missing route, a clock that goes backwards or does not advance, or more than MAX_SLEEP_ROUNDS (16) msleep calls for one sleep ends the component with exit 1. The round cap is a bounded mechanical limit that stops a spin. None of these checks reads the request, the subject, or anything Bend computed. The only Writ-visible effect is availability: a bad clock stops every client. Note that the timer route itself is the integrator's choice.

Confirm by reading:

  1. writ_shim_log writ_mem.cc:1252-1256 passes the bytes unchanged to Genode::log (up to len or the first NUL); it filters, labels, or adds nothing, and a null pointer does nothing.
  2. writ_shim_sleep_ms returns only once the session clock has advanced by at least ms, and otherwise ends the component with exit 1 on a backwards clock, a non-advancing clock, or the round cap writ_mem.cc:1272-1286.
  3. The route probe treats only DENIED as no route; a quota answer counts as a route and is left to the Connection, and the probe session is closed again writ_mem.cc:1223-1236.
  4. writ_shim_now_ms writ_mem.cc:1259-1263 returns the timer's elapsed_ms(), or 0 before construct, and nothing else.
