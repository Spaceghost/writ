Taking Genode's capability ideas into Writ's own model

Change add-genode-capability-adoption. A pure-Bend module that models object capabilities the way Genode does them, composes it with Frontend, and says out loud which Genode semantics Writ adopts and which it refuses. No native code. Proposed; nothing built.

Two models that have to agree

Writ's Frontend today

  • A capability is a record: 256-bit token compared in full, subject, exact plan, rights bits, authority epoch, expiry.
  • Transitions: mount, open, dup, attenuate, close, resolve. Each checks a revision and returns the old state on denial.
  • Public data constructors. Nothing is unforgeable; the monitor is trusted to build these from authenticated state.

Genode's object capabilities

  • A capability refers to an RPC object. Each protection domain sees its own local selector for it.
  • Delegation is passing a capability in an invocation. Possession generally permits further delegation.
  • Sessions are created through the parent, which routes and labels them. RAM and capability quotas are accounted per domain.
  • Destroying the object invalidates every reference to it.

The Genode host spec already says in prose that native selectors are local, that delegation cannot impersonate the reader, and that labels are not identity. If those rules are implemented only inside the C++ shim, the shim is making policy. If they are implemented in Bend with tests and laws, the shim stays thin and the same binding model can be replayed on every host.

The module

A new Bend module (provisionally HostBinding.bend) beside Frontend, not inside it. Existing frontend requirements CF-001 through CF-014 do not change.

Adopted and rejected

Adopted from Genode

  • Parent-mediated routing is the session-binding primitive. The parent-prepended label prefix is the only identity source. A suffix is resource intent.
  • Destruction invalidates aliases. Revocation is object destruction plus a generation bump. There is no "revoke one copy," because Genode cannot do that either.
  • Quota saturation denies first. No RAM or capability quota, no object, no Writ check. The ledger is untouched.

Rejected from Genode

  • Possession is not the subject. An alias in domain D proves D can invoke the object, not that D is the reader who mounted it. Frontend.Caller stays the authenticated subject.
  • Delegation does not widen. A delegatee gets at most the bound handle's rights, matching the frontend's attenuation rule.

Each adopted and rejected item becomes a Bend test that also emits a canonical vector: initial state, transition, expected outcome, with no native selector values. Lane A's Genode component replays those vectors against real sessions. That is how the portable host contract's "decision and native tests" requirement gets satisfied without inventing a second policy implementation.

Requirements

GA-001Native objects carry a generation; an alias is valid only while generations match.
GA-002Mount binds through a parent route whose prefix names the authenticated subject; suffixes contribute nothing.
GA-003Open and attenuate mint new objects; never an alias to the parent object.
GA-004Close destroys the object so every alias in every domain fails; applies Frontend.close.
GA-005Possession is not the subject; holder must equal the binding's subject unless an explicit recorded delegation covers it.
GA-006Delegation cannot widen rights.
GA-007Quota saturation denies before any Frontend or ledger check.
GA-008Every denial returns the input state and a reason from a closed error type; proven as a law.
GA-009Vectors are generated by the tests, byte-identical across runs, and replayable by hosts.

Milestones

  1. The module with its five records and closed error type typechecks.
  2. Five transitions composed with Frontend. Denial returns the input state.
  3. Tests for every adopted and rejected semantic, in the existing Test.bend style.
  4. Two laws in LAWS.bend: denial preserves state, generations are monotone. Proven in PROOF.bend.
  5. Vectors emitted under verification/; mapping table from GN and PH requirements to vectors, gaps marked reviewed-only.
  6. Added to Tests.bend; full suite on both backends; manifest and verification record updated.

Where a subagent starts

This lane needs nothing but the pinned Bend toolchain. It is the one that can start today. The subagent should read Frontend.bend end to end, the capability-frontend baseline spec, and GN-003 through GN-011 in the Genode host spec, then write the records and the closed error type first and get --check-only green before any transition. Tests follow the check(ok, name) convention and the no-if style. It must not modify Frontend.bend; the module composes with it.

Coordination with lane A: the shape of Route and Binding is what Genode.accept will construct. Agree on field names early and leave them stable.
