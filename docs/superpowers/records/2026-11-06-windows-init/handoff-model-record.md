# Synthetic handoff model

A worker report followed by a repeated handoff must not create a second protected delivery. `HostHandoff.bend` models only trusted-monitor preflight sequencing and delegates actual admission to the unchanged `HostPrimitives.admit_worker`; it is not a Windows IPC adapter or security qualification. Its 37 synthetic `HH-*` checks are included in the 2,102-check core suite. Native facts and current local/core state are trusted inputs; a revision value cannot independently prove that an OS fact was freshly measured.

The model's `Aborted` result carries a terminal `Retired` local state and records fail-stop without changing the HostPrimitives authority state or emitting an effect. An admission attempt consumes the local phase and wraps the exact `P.Step` returned by the existing gate; it constructs no additional effects. A denied attempt returns its unchanged core state, and native cleanup after any consumed attempt remains a host obligation. Stale local revision preserves the state; the trusted stream adapter must separately poison/retire a failed stream. Existing `admit_worker` checks its own revision, resolves the current session/reference, configured profile and control/inventory facts, and emits its original `DeliverInputs` only on acceptance. This wrapper does not perform a DataOS/Backplane final commit, prove publication or revalidate unmodeled budget/epoch/scope at commit; those remain with existing gates. Atomic installation and ordering against revocation/restart, route completeness, peer authentication, native cleanup, externally visible diagnostic channels and continuous Windows enforcement remain unimplemented host obligations. See [portable-host traceability](../../../../openspec/traceability/portable-host-contract.md) and the [handoff inventory](handoff-inventory-and-model-design.md).

No strict worker gate, native Windows path, production law, policy release decision or prior native evidence changed. Windows byte-worker confinement remains incomplete.
