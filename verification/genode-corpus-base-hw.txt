  Command: cd ../writ-genode/build/x86_64-hw && MAKEFLAGS= make run/writ_bend_overflow
  Run 1 (shim 3b71f36c), log ../writ-genode/run-hw-writ_bend_overflow-1.out, rc 2, 42 s:
    [init -> writ_bend_overflow] writ_mem: unresolved fault at 0x2206c00000 (chunk could not be attached: attach OUT_OF_CAPS), component terminates
    [init] child "writ_bend_overflow" exited with exit value 139
    Error: at the default quota the expected outcome is a guard-page refusal, got: chunk could not be attached: attach OUT_OF_CAPS
  Cause: core charges each attached piece's metadata to the RM session, which
  core creates with 64 KiB and 2 caps (repos/base/include/rm_session/connection.h).
  Rm_connection::create upgrades on demand (8 KiB / 2 caps per retry); attach
  does not, so the recursion's later chunks exhausted the session. The PD
  itself still had quota. Fixed in the shim, not in the run script (SHIM CHANGE).
  Run 2 (shim 67cc3617), log ../writ-genode/run-hw-writ_bend_overflow-2.out, rc 0:
    [init -> writ_bend_overflow] writ_mem: unresolved fault at 0x2280000000 (guard page), component terminates

SHIM CHANGE (population function: _attach_pieces)
  hosts/genode/shim/writ_mem.cc 3b71f36c... (M1/M2) ->
  67cc36171d0888ee9119245f72bd1ea4dfde1a1740f8a69d98c5b7a6e78b32ff
  On an attach refused with OUT_OF_RAM or OUT_OF_CAPS, _upgrade_rm_session
  upgrades the RM session by 8 KiB or 2 caps (Rm_connection::create's
  amounts) through Connection::upgrade, at most 4 times per piece, and only
  while the PD keeps RAM_MARGIN and CAP_MARGIN after the transfer. It is a
  session upgrade from the component's own quota (child.cc, Child::upgrade),
  not a resource_request; Env::upgrade blocks only on PENDING
  (component.cc:226-232). When the PD cannot pay or the bound is reached, the
  named attach error stands. The run script's quota was not raised.
  Live copy ../writ-genode/writ-repo/src/writ_shim/writ_mem.cc: cmp identical.
