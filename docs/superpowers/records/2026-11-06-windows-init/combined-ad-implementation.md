# Combined A/D exploratory implementation

The [design](exploratory-combined-ad-design.md) proposes A/D/D/A fixed no-data LPAC lifetimes: A has zero capabilities and Win32k disable ON, while D has one enabled registryRead capability and Win32k disable OFF. This is a joint-status observation of two deliberately changed fields, not a single-factor or causal contrast. This distinct-branch implementation has not been built or run on Windows.

D has no proven GUI or ambient-resource confinement. The fixed child adds no clipboard, screen/input, window-enumeration, COM activation or socket/traffic probes, and has no Writ session, policy, canary, caller-selected data or handles. `WSAStartup` can cause unobserved provider/OS activity; the child issues no explicit traffic. The actual capability list must match exactly the requested A or D state, and the actual full creation-policy input and the retained child's system-call-disable readback must match the requested A or D state. Unknown/reserved bits, differences in other known policy bits or missing readbacks are incomplete. Selected remaining token facts are compared privately, so raw token sets cannot be independently reconstructed from logs. Constructed environment input is compared but the child's full environment is not independently read. Package/OS state, ordering, drift and PSS perturbation remain potential confounders; the pre-resume PSS table cannot establish later handle state.

The controlled workflow uses trusted `RUNNER_TEMP` for fixed build/log paths; an independent caller can change that environment, so its no-data path guarantee is scoped to the workflow. The exact-ref dispatch guard and separate job are temporary and must remain off master. The supervisor stops after any failed case, timeout or uncertain cleanup; child-exit uncertainty retains shared WFP/profile until disposable-VM fallback. Normal cleanup checks the owned dynamic WFP session and separate readback of all four filter IDs. `CoTaskMemFree`, `FwpmFreeMemory0` and `DeleteProcThreadAttributeList` report no status. Synthetic classifiers do not test native API failure/control flow; Windows build and runtime remain unverified. No result establishes cause, byte-worker confinement or host qualification, and the strict worker and gate remain unchanged.
