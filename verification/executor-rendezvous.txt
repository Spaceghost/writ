## Laws added by this change (LAWS.bend, proved in PROOF.bend)

The module also relies, unmodified, on the existing law `failed_check_denies`:
every transition computes acceptance as Guard.all over its ordered gate
list, so a failed rendezvous check at any position denies.

- nat_lt_irreflexive: no Nat is below itself under Nat.is_lt. Auxiliary
  arithmetic for offer_order_irreflexive; says nothing about the
  rendezvous by itself.
- nat_eq_reflexive: every Nat equals itself under Nat.is_eq. Auxiliary
  arithmetic for offer_order_irreflexive; says nothing about the
  rendezvous by itself.
- offer_order_irreflexive (ER-003): before(a, a) is False for every offer,
  so the comparator is strict on its diagonal at all three levels (quote,
  provider id, serial) and list order cannot pick among records under one
  identity. Limits: transitivity, totality on distinct identities, and that
  `best` returns the minimum are not proved.
- rendezvous_ineligible_offer_dropped (ER-002): an offer that is not
  `eligible`, at any position and whatever its quote, leaves
  eligible_offers (the only list `select` ranks) unchanged when removed.
  Limits: does not prove that `select` ranks only that list (structure and
  tests show it), nor that the eligibility gates are the right ones.
- rendezvous_stale_selection_keeps_state: `select` at one past the state's
  revision is not accepted and returns exactly the supplied state, so a
  selection ranked before a submission, withdrawal or abandonment moved the
  state cannot commit. Limits: the successor revision only (other stale
  revisions are tested); says nothing about the reason; does not claim the
  host serializes installs.
- rendezvous_wrong_provider_evidence_rejects (ER-005): when `from` is not
  the provider the stored selection names (including no selection),
  `submit_evidence` is not accepted and returns exactly the supplied state.
  Limits: pins the outer selected_provider_is match only; substitutions by
  the selected provider itself, the selection's currency and the projection
  are tested, not proved.
- rendezvous_unselected_dispatch_rejects (ER-001, ER-007): when the offer,
  worker session or its binding is not the stored selection's dispatch
  target (including no selection), `dispatch` is not accepted and returns
  exactly the supplied state. Limits: pins the outer target match only;
  that an accepted dispatch is correct (host currency, selection currency,
  caller token, evidence, trial, replay) is tested, not proved; does not
  claim the host executes only recorded dispatches.

Tested, not proved: the transitivity and totality of `before` on distinct
identities and the order independence of `best` (ER-003, the two-order
selection checks); every inner gate of `select`, `submit_evidence` and
`dispatch` and every projection filter (one named denial check each, pinned
by the mutation sweeps). No planned law failed to check: none was left out
or weakened.

## Not exercised

- Transport authentication: every `from: I.Principal` is a synthetic
  fixture. No Genode route, Linux peer credential or Windows token is
  verified for providers or approvers.
- Signatures: no offer or approval carried off-host is cryptographically
  verified; Bend checks no signature.
- Durable state: the rendezvous and issuer states live only in the test run.
  Nothing is persisted, recovered or rolled back, so `seen`, `retired`, the
  withdrawal flags, the evidence and the dispatch records are not preserved
  across crashes by anything here.
- Concurrent hosts: there is no serialization of installs between hosts or
  processes. Races are modeled by the revision check only.
- Per-use projection rebuilding by a host: the tests rebuild
  negotiation_context, commit_context and provider_registry at each use
  themselves; no host does.
- Trial metering: add-metered-sample-execution is not implemented; trial
  compute is unmetered, as in Negotiation.
- Settlement: the selected quote is not settled against the ledger hold; the
  quote is a ceiling, and exact-versus-ceiling semantics are pending
  Spaceghost (q18).
- That the committed output came from the reported worker: commit_context
  binds the commit to the dispatch record (selection, host incarnation and
  reported worker session) and to the selection's trial session, and that is
  executed. Bend does not see which worker produced the candidate; the host
  must run only the worker it admitted, report its session truthfully, and
  pass commit_context, rebuilt, to every commit (reviewed-only in the
  traceability).
- The same session at the commit: the host passes the same Negotiation
  session to commit_context and to the commit; Bend cannot tie them, because
  the commit takes its session separately (Backplane.commit and
  DataOS.commit_from_capability read their own session argument), so
  session_follows_selection protects only the session commit_context is
  given (reviewed-only; task 7 re-review item R1).
- Any native host: no Genode, Unikraft, Linux, Windows or rclone binding runs
  the rendezvous. The HostPrimitives leg is the Bend model only.
- GPU: no device code ran; this CPU run is not a GPU test.
