3. Mechanism as built, and how it differs from the brief
-------------------------------------------------------

Reservation: a qualifying mmap (len >= 1 GiB, PROT_READ|PROT_WRITE,
MAP_PRIVATE|MAP_ANON, no MAP_FIXED/MAP_SHARED, fd -1, offset 0) creates a region
map of the page-rounded size with Rm_connection::create and attaches its
dataspace through Env::rm() (at the address hint if one is given and free,
otherwise anywhere). Nothing is populated.

Population: 2 MiB chunks, each a RAM dataspace from the component's own PD
(Pd_session::alloc_ram), attached into the region map at the chunk offset.
Before allocating, the shim checks Pd_session::stats().ram.avail() >= chunk +
64 KiB, so a fault never becomes a blocking resource request.

Guard: mprotect(PROT_NONE) on a page-aligned range inside a reservation is
recorded as a guard. Each populated chunk overlapping it is detached and the
SAME dataspace re-attached as the pieces outside the guard (Region_map::Attr
size/offset), so bytes outside the guard are kept and the guard range has no
mapping. The fault handler never populates a guard. Lifting a guard
(PROT_READ|PROT_WRITE over it) and any other prot value fail with -1 ENOTSUP.
mprotect outside every reservation is forwarded to libc (-1 ENOSYS).

munmap: only the whole reservation (exact base, page-rounded length) is
accepted; it detaches each chunk's pieces, frees each chunk dataspace
(free_ram), detaches the region map from Env::rm(), and destroys it. A partial
munmap of a reservation fails with -1 EINVAL. Other ranges go to libc.

Fault delivery (DEVIATION from the brief). The brief asks for a Genode fault
handler (region-map fault signal). On base-linux that signal is never
delivered (region_map.h doc comment; region_map_client.cc:49-56 is an empty
body), and an unpopulated managed-dataspace page is a PROT_NONE Linux mapping,
so the touch is a Linux SIGSEGV. The shim therefore installs its own Linux
SIGSEGV handler with the raw rt_sigaction system call (SA_SIGINFO |
SA_RESTORER | SA_RESTART | SA_ONSTACK, own rt_sigreturn restorer), the same way
base-linux installs its exception handler, at the first qualifying mmap. The
handler resolves the fault on the faulting thread and returns, so the access
is retried. Every refusal (guard page, outside every reservation, populated
chunk, chunk could not be charged) prints one line with Genode::raw, sets
SIGSEGV to SIG_DFL, and returns; the retried access faults again and Linux
kills the process. The region-map fault-signal front end needed on base-hw,
NOVA, or seL4 is NOT built and NOT exercised here.

Reaching libc's originals: the binary defines mmap/munmap/mprotect (and
exports them in .dynsym: readelf --dyn-syms shows mmap, munmap, mprotect
GLOBAL DEFAULT in section 1), so calls from the probe bind to the shim at
static link time. The originals are looked up with
Shared_object(env, heap, "libc.lib.so", BIND_LAZY, KEEP).lookup(...); the shim
refuses to start if a lookup returns its own function. Observed: libc
mmap=0x16d14bc0, munmap=0x16d0aa00, mprotect=0x16cfc150; shim mmap=0x10071d0.
No libc override mechanism was needed: link order plus that lookup worked.

7. Limits
---------

- base-linux (Genode-on-Linux) only; not native; nothing about base-hw/NOVA/seL4.
- The fault front end is base-linux-specific (raw Linux rt_sigaction) and runs
  a PD RPC (alloc_ram) and a local region-map attach from signal context on
  the faulting thread. Safe for this single-threaded probe; with several
  lanes, a fault while the same thread holds a Genode lock the handler needs
  would deadlock. Not tested with threads.
- The shim's SIGSEGV handler replaces base-linux's process-wide after the
  first qualifying mmap; for faults outside every reservation it prints its
  own line instead of base-linux's "Segmentation fault (signum=11)" and still
  terminates. SIGBUS, SIGILL, SIGFPE keep base-linux's handler.
- Not exercised: the "chunk could not be charged" refusal (touching more than
  the quota), address hints (the runtime's corpus_at probes hints from 2^45
  down), partial-munmap refusal, more than one reservation, more than 4096
  pieces in one region map (base-linux MAX_REGIONS; an 8 GiB reservation
  fully touched is exactly 4096 chunks plus any guard split pieces).
- Bounds: 32 reservations, 4 guards each, 2 MiB chunks, 1 GiB threshold.
- The probe is a C stand-in; the Bend runtime has not run with the shim yet
  (Task 2).
