Bend 2, as Writ uses it

A working primer for someone who has never written Bend. It covers the parts of the language this codebase leans on, the mistakes the checker will catch on your first day, and how to run things. Pinned toolchain: Bend 2.0.39.

Setup on this machine

Bend 2.0.39 is now installed under your home directory, exactly as docs/INSTALL.md prescribes, without touching your shell profile. Put it on PATH in any shell where you work on Writ:

export PATH="$HOME/.local/share/writ-toolchains/bend-2.0.39/bend/bin:$PATH"
export BEND_NO_TELEMETRY=1
bend version        # bend 2.0.39
bend guide          # the official language guide, read it once end to end
bend guide shaders  # before you touch anything with a ! call
bend base Map       # the Base library, one name and everything under it

Bend 1 and HVM are different systems. Anything you find online about them does not apply here.

The shape of a program

Syntax looks like Python. Semantics are closer to Haskell and Lean: pure, typed, almost no inference, and every function must provably terminate. A file is a list of datatypes and functions, and a main that returns IO gets compiled and run.

import Base

type Shape is Data:
  Circle{r: U32}
  Square{s: U32}

def area(x: Shape) -> U32:
  match x:
    case Circle{+r}:
      (3 * r * r : U32)
    case Square{+s}:
      (s * s : U32)

def main() -> IO(Unit):
  do IO<Unit>:
    IO.print(U32.show(area(Square{5})))

Three things to notice already. Every constructor is written with braces, even when empty: True{}, Nil{}, None{}. Arithmetic is wrapped in parentheses with a type: (a + b : U32). And +r in the pattern marks a field you intend to use twice.

Affine by default: the + rule

This is the rule that generates the most first-day errors. A variable may be used at most once unless you mark it reusable with +. Reusable requires the type to be Data (copyable); functions, arrays, and IO handles are Type and can never be copied.

# -A: erased (gone at runtime), n: affine (default), +x: reusable
def replicate(-A: Data, n: Nat, +x: A) -> List<A>:
  match n:
    case 0n:
      Nil{}
    case 1n+p:
      x <> replicate(A, p, x)   # x used twice: allowed because of +x

Writ marks parameters with + all over the place, and you will see +List<State> in record fields. That plus means the whole list is reusable (List<&2, State>). Dropping an affine value is always free; using it twice is the compile error.

Rule of thumb: when the checker complains about a variable used more than once, add + at its binding site (parameter, pattern, or +x = ... let). If it refuses because the type is not Data, restructure so the value is threaded through and handed back.

Match, termination, and definition order

There is no if. You match on True{} and False{}. Writ's Guard.choose and every check helper are written this way.

def choose(-A: Type, allowed: Bool, yes: A, no: A) -> A:
  match allowed:
    case False{}:
      no
    case True{}:
      yes

Matching has sharp rules that feel odd at first but keep proofs sound:

  • You can only match a parameter or a pattern-bound variable. match f(x): is rejected. To branch on a computed value, pass it to a helper that matches on its own parameter. That is why Writ is full of small *.checked, *.go, and commit_resolved helpers.
  • Recursion must shrink. A recursive call has to pass a smaller piece of a matched parameter, and that shrinking parameter should come first in the argument list. A loop bounded by the outside world takes a Nat fuel argument and counts it down; Writ's solver has max_rounds for exactly this reason.
  • No mutual recursion, and a def may only call defs above it. Order your file bottom-up. Two mutually recursive functions become one def with a selector argument.
  • Multi-scrutinee match is normal: match a b: with case Bits64{al, ah} Bits64{bl, bh}:. A _ catches the rest.

@unsafe defs skip the termination check. Writ's rules forbid them in the library; the proof gate names every def that depends on one.

Numbers, literals, and annotations

TypeLiteralNotes
U324232-bit words. Bit ops U32.and/or/xor/shl/shr. Writ builds 64-bit flag sets from two of these (Bits64{lo, hi}).
Nat7n, 1n+pUnary naturals for counting, IDs, fuel, proofs. The compiled runtime caps arithmetic at 2^48−1. Pattern 1n+p peels one off.

Operators only work inside a typed parenthesis: (count + 1 : U32), (index - 1 : U32). Comparisons are plain calls: U32.is_eq(a, b), Nat.is_lt(now, deadline). The == symbol is reserved for equality types in laws, never for runtime comparison. When the checker cannot decide a type, annotate: {3 : U32}.

IO blocks

Effects live in IO and are sequenced with do. Every bind is annotated with its type. A step with no binding must produce Unit.

def main() -> IO(Unit):
  do IO<Unit>:
    IO.print("Flow: a summary keeps its report's restrictions.")
    candidate : Core.Candidate <- Expect.solved(Core.solve_cpu(Scenario.graph(), 0n))
    explain(candidate)

That is the real main of examples/Flow.bend. Two Base calls you will use in tests and examples: IO.print and IO.die(A, status, message), which exits the process. Writ's Test.bend and examples/Expect.bend are nothing more than thin wrappers over those two. do works on any monad with bind and pure, so you will also see do Maybe<&2, U32>: blocks in the guide.

Laws and proofs

A law is a claim. A def of the same name is its proof. A proposition is a type; {a == b : T} is an equality type and {==} proves it when both sides compute to the same term. Matching refines the goal per case, and a recursive call is the induction hypothesis.

# LAWS.bend (humans own it; the claim)
law denied_selects_original:
  for -A: Type
  for proposal: A
  for original: A
  {Guard.choose(A, False{}, proposal, original) == original : A}

# PROOF.bend (the evidence; imports LAWS.bend)
def Laws.denied_selects_original(A, proposal, original):
  {==}

The convention is two root files: LAWS.bend states, PROOF.bend proves. bend PROOF.bend prints ALL PROOFS CHECK or names the failures. --verdict rechecks with a small kernel that has its own proof in Lean 4; that needs a working Lean install, which this repo's verification record says was not available. Writ currently keeps three laws about guards and preservation of denied state. Backplane, the reference app, keeps over three thousand. Same mechanism.

Parallelism and the ! call

A parallel let runs two calls at once: a b = f(x) g(y). You promise the compiler they are independent (purity makes this automatic) and roughly equal in cost (your job). A bang, f!(x), hands that call and every parallel call inside it to the GPU.

def pow2(+n: Nat) -> U32:
  match n:
    case 0n:
      1
    case 1n+p:
      a b = pow2(p) pow2(p)   # fork-join, balanced
      (a + b : U32)

def main() -> IO(Unit):
  IO.print(U32.show(pow2!(20n)))

What a ! does not prove: that anything ran on a GPU. The JavaScript target runs everything sequentially. A native build without a device, or with +RTS --gpu off, runs bangs on the CPU pool. Writ's own docs say this bluntly, and AGENTS.md requires you to report it the same way: a CPU fallback is not a GPU test.

Writ's device-facing entry points are Gpu.bend, GpuLibrary.bend, DlmGpu.bend, and TransferGpu.bend. Everything they produce is re-verified on the host by code that does not share their work tree. Read bend guide shaders before editing any of them.

Modules and imports

A module is a file. An import gives it a local alias, and that alias prefixes every def in it. Dots inside names are just characters, so Core.verify inside Core.bend is simply a def named verify seen from outside, and Bits64.join is a def whose name happens to contain a dot.

import Base
import ./Core.bend as Core
import ../Core.bend as Core          # from inside examples/
import ./CoreTests.bend as Core      # Tests.bend aliases the test module the same way

All of Writ's imports are local paths. Base comes with the compiler. Nothing is fetched from BendHub, and nothing should be published there.

A first exercise inside Writ

Write a tiny module that uses the library the way the examples do. Save this as examples/Hello.bend in the repo (or anywhere beside Expect.bend), then run it with bend examples/Hello.bend.

import Base
import ../Core.bend as Core
import ./Expect.bend as Expect

# Two 64-bit flag sets. Bit 0 of the low word is Writ's "incident team" secrecy bit.
def team_only() -> Core.Bits64:
  Core.Bits64{1, 0}

def public() -> Core.Bits64:
  Core.Bits64.zero()

def main() -> IO(Unit):
  do IO<Unit>:
    IO.print("Hello: labels only grow along a flow.")
    # join is set union: public joined with team-only is team-only
    Expect.boolean(Core.Bits64.equal(Core.Bits64.join(public(), team_only()), team_only()),
      True{}, "join keeps the restriction")
    # subset asks "does every bit of a appear in b?"
    Expect.boolean(Core.Bits64.subset(team_only(), public()), False{},
      "team-only data does not fit a public clearance")

Expected output is two PASS lines. Then try the breakage: flip the second expected value to True{} and watch the process exit with status 1 and an expected-versus-observed message. That fail-fast style is how every Writ example and test is written.

  1. Read Guard.bend (30 lines). It shows a datatype, a fold, and the no-if style.
  2. Read examples/Expect.bend and examples/Flow.bend. That is an IO block calling the real library.
  3. Read the first 220 lines of Core.bend: records, Bits64, and the checked list lookup that never wraps an index.
  4. Run bend Tests.bend. It takes a minute and ends with ALL LIBRARY TESTS PASSED.
