What Writ decides, and what it refuses to

Data carries its terms.

Writ is a Bend 2 library for information-flow control, capability-bound operations, and multiparty transformation approval. It answers one question: may this operation move these exact inputs to this exact destination under the authority that exists right now?

One story runs through everything

Every example, test fixture, and doc uses the same scenario: a restricted incident report becomes an approved internal summary. The report belongs to the incident team and contains reporter-supplied claims. A summary must keep both facts. Shortening a document does not make it public, and it does not make its claims trustworthy.

The central claim: changing bytes never authorizes release. Copying, ROT13, encryption, compression, hashing, summarizing, and embedding all keep their source's restrictions. Writ follows dependency and authority, not byte similarity. An approved transformation may change the schema (document to summary), but secrecy and untrusted provenance only accumulate.

How a write gets authorized

A solver proposes. An independent verifier checks the proposal against the original constraints. The commit path rechecks live authority before producing a scoped write intent. Nothing in the library performs the write itself.

Each node in the constraint graph carries four things: a type domain (which shrinks by intersection), a secrecy set, an untrusted-influence set, and a required-effects set (all three grow by union). The three edge kinds:

EdgeDirectionConsequence
flowsource → dependent resultSecrecy and untrusted influence accumulate. Includes control dependencies, not just data.

The verifier is the stronger separation in the system. It reads the original seeds and every original edge and does not reuse the solver's propagation helpers or convergence claim. That is what catches the stripped_candidate in examples/Flow.bend: a proposal that keeps the real report seed but quietly drops the summary's inherited labels.

Two authority domains stay separate on purpose. Read and write are distinct grants; neither follows from holding a reference to the data. Possessing broad permissions somewhere in the system is not enough; both grants must cover this exact plan. Owning the destination bucket gives you no power to weaken what lands in it.

The negotiation session

A session advances through guarded transitions. Each step preserves the immutable request, checks the current revision, and returns the original state on failure.

Proposed→CandidateFixed→Challenged→Sampled→OwnersApproved→Reserved→Running→Committed
  • Pinning fixes the candidate's identity. A challenge is only valid if issued after the pin.
  • Sampling is a bounded trial, gated by sample_permit before any data is read. Passing a sample never removes labels; every contributing origin must still approve.
  • Reservation moves execution units out of the reader's available balance. Commit consumes the hold. Cancel or expiry refunds it. Receipts are never recycled.
  • Commit re-resolves the live capability descriptor, checks the caller is the negotiated reader, and runs every backplane gate again. A revoked capability means Rejected with the supplied session and ledger unchanged.

Status and limits, stated plainly

The repo is unusually careful about not overclaiming, and AGENTS.md asks you to keep it that way. What exists:

  • An executable security-core library and protocol model, entirely in Bend 2. Tests, examples, and proofs pass on the JavaScript backend and on a native CPU build.
  • Finite property coverage: a Floyd–Warshall oracle checks 320 graph cases against both the reference and the parallel producer.

What does not exist yet, and must not be implied by a green run:

  • Physical GPU execution. Every recorded run used --gpu off or the sequential JavaScript runner.
  • Independent Lean kernel verification. The --verdict step could not start on the recording machine.
  • Real POSIX devices, worker confinement, authenticated grant issuance, durable storage, payment settlement, hosted-language execution. All are OpenSpec change proposals, not implemented adapters.
  • Declassification or endorsement. Intentionally absent from the release path.

Every public Bend data constructor in this library is a description, not a capability. Deserializing a Ticket, Session, or WriteIntent from an untrusted caller and treating it as authority is the one thing the design forbids above all others. Authority comes from monitor-owned state, authenticated before the call.

Host platforms

Genode is the reference capability platform: trusted parent routing establishes session authority and the Writ service runs the full Bend checks on top. Direct Linux, native Windows, and a future kernel using Drift for drivers are separate targets sharing one Bend decision core. All host ports are proposed; the current execution evidence is for the library only. A native handle or descriptor is never a portable credential, and bearer possession alone does not establish the original caller's identity. docs/PLATFORMS.md is required reading before touching any native boundary.

The optional contrib/rclone/ remote is the one sanctioned place with Go: a thin interface adapter for rclone. Policy and the reference service there are still Bend.
