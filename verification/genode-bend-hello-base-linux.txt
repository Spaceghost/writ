BLOCKING ERROR
  Symbol: mprotect (called from pool_stack in hello.c, stack guard page).
  Genode 26.08 libc: weak dummy, returns -1 (repos/libports/src/lib/libc/dummies.cc:126).
  Why no build-configuration fix: the only flag-level route would be a
  -D macro that turns mprotect into a no-op returning 0. That removes the
  guard page between the evaluation stack and the alternate signal stack,
  i.e. it silently drops the runtime's stack-overflow fail-stop. It edits the
  evaluator's behavior by preprocessor instead of by text, so it is outside
  the task's rules, and it would hide exactly the fault row Task 3 must
  measure. Not done. (E2's MAP_NORESERVE=0 differs: it restores the meaning
  the flag has on the libc's own ABI and drops no check the runtime makes.)
  For Task 3: memory row: the 8 GiB reservation is committed and zeroed, not
  reserved (needs 8 GiB + 16 KiB quota; at 256M the libc blocks rather than
  failing); faults row: mprotect is missing, the guard page cannot be made,
  and startup stops there; event loop, threads, clock, process rows: not

  (cpu_count, called first in main), getenv("BENDRTS"), and _exit(1) from
  err_fail (the component exited with value 1; it did not hang).

FAULTS: EXPECTED INTERACTION (recorded, not executed here)
  The runtime registers err_trap for SIGSEGV and SIGBUS with sigaction and
  an alternate stack with sigaltstack (pool_stack, hello.c:1674-1680). Genode's
  libc only emulates both (repos/libports/src/lib/libc/signal.cc:117-130 and
  234-266): nothing reaches the Linux kernel, so err_trap never runs for a
  hardware fault on base-linux. After the first qualifying mmap the shim's
  raw rt_sigaction handler is the only Linux SIGSEGV handler in the process.
  A touch of the stack guard would therefore print the shim's line
    writ_mem: unresolved fault at <addr> (guard page), component terminates
  and not "bend: memory fault (machine stack overflow?)". No guard hit
  through the Bend program was run in this task (Task 3 runs Overflow.bend),
  and nothing here reproduces verification/runtime-profile-fault.txt.
  Note also that the shim handler runs on the faulting stack (no
  SA_ONSTACK): a machine-stack overflow, as opposed to a touch of the
  runtime's term-stack guard, dies without the shim's line.
