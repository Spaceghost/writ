## The restructuring

- **Stage handles (`Kept`).** The native backend unboxes every record and every non-recursive sum into one word per field. An `R.Change` is 85 words (its `R.State` is 83), an `N.Step` 27, an `N.ReservationStep` 32 and an `N.Context` 34. The probe showed that a world holding several such values, or a def holding a world beside the states it reads, goes past 247 words, and building such a world in one def fails as well, because every field is live at the constructor. A recursive type is never unboxed. `type Kept<a, A>` (`Kept{value}` | `Rekept{inner}`) is therefore one word. `Rekept` is never built; `Kept.value` is total. The typed helpers are `keep_change`/`kept_change`/`kept_state`, `keep_step`/`kept_session`, `keep_reservation`/`kept_reservation` and `keep_context`/`kept_context`. Measured with `bend ... -o x.c` and the arity table in the C: the largest RendezvousTests def is now 210 words; it was 243 on master.
- **Trial world `Tw` (Sections 1.3 to 1.5).** `trial_world()` and `trial_world_on` build each stage once through the same entry points: `R.select`, `proj_on`, `N.challenge`, `submit_t`, `N.sample`, `reserved_on`, `N.start` and `R.dispatch`. The former zero-argument fixtures keep their names as accessors on `tw`: `trial_select`, `selected_t`, `proj0`, `challenged_t`, `evidence_change`, `evidenced`, `proj1`, `sampled_t`, `reserved_t`, `ledger_t`, `running_t`, `dispatch_change` and `dispatched_t` (plus `reservation_t`). Every fixture that depended on them gained a leading `+tw: Tw` parameter (113 defs, among them `submit_a`, `trial_denied`, `dispatch_on`, `dispatch_a`, `dispatch_denied`, the `b_*`/`selected_b`/`challenged_b` phase-2 chain, the `sub_*` chain, `final_proj`, `kept`, the integration contexts and the existing `_K_J` conjuncts). A script did this threading and the wrapping: each check K of an IO group G whose expression reads the world became the def `G_K(+tw: Tw) -> Bool`, holding the unchanged expression with `f()` replaced by `f(tw)`, and the group now calls `Test.check(G_K(trial_world()), "<same label>")`. The host fixtures (`host_id` to `worker_b`), `reserved_on`, `running_on` and `offer_id_ta`/`offer_id_tb` moved unchanged above Section 1.3, because Bend requires a def to be defined before its callers and the world needs them. `challenged_for` moved below the world.
- **Scenario worlds (Section 2.1).** `Sc` (built by `sc_world()`, `sc_world_selected` and `sc_world_trial`) holds A's lifecycle at 110: the issuer, the last approval's Change, the pin, selection 5, challenge 41, A's evidence, sample, owners, reservation, start and dispatch. `ScB` (`sc_b_world(w)`) holds the abandon and reselect of B's {202, 2} through B's dispatch at 116. `ScA2` (`sc_a2_world(w)`) holds A's reselection after the dispatched abandon through A's second Running session. The accessors keep the old names with a `w`/`b`/`a` argument (`sc_issuer(w)`, `sc_approved(w)`, `sc_selected(w)`, `sc_evidenced(w)`, `sc_running(w)`, `sc_dispatched(w)`, `sc_reselected(b)`, `sc_b_running(b)`, `sc_a2_running(a)`, ...). Variants are built from the shared stage exactly as before: `sc_revoked(w)`, `sc_unapproved_a(w)`, `sc_partial(w)`, the twins, `sc_select_on(w, ...)`, `sc_dispatch_on(...)` and the commits. `sc_issuer()` became `sc_registered()`, called once per world. `sc_put_offer`, `sc_put_approval` and `sc_approve_all` take the issuer instead of rebuilding it. `sc_approve_all_change` returns the last approval's Change. `sc_dispatch_in` is the dispatch on a supplied projection, and `sc_dispatch_on` delegates to it. Each scenario check is `G_K(w)`, called on a fresh `sc_world()`; the scenario checks that were inline in their IO defs moved into these defs unchanged apart from `(w)`.
- **One semantic note.** In both worlds the sample, approve, reserve and start steps and the world's own dispatch read one projection of the evidenced state. Before, each use rebuilt that projection. The values are equal because Bend values are immutable and the inputs are the same. The label "scenario current authority: on projections rebuilt for each use ..." still describes the host's procedure, and the comment above `Sc` says so.
- Comments: one sentence in the header (why stages are built once per check), a "Stage handles" section, the `Tw` and "Scenario worlds" comments, and the `G_K` / `G_K_J` naming. The fixture value discipline is unchanged. All 229 checks keep their labels and order.

## Left over / concerns

- The QEMU guest run was not repeated here. At the earlier ratio (about 13 times the host QuickJS time) the corpus would take roughly 105 to 175 s of the 600 s limit. That figure is an extrapolation, not a measurement.
- `Kept` relies on the pinned backend's unboxing rule (recursive types stay one word). This was measured on 2.0.39 only. A toolchain that unboxed it would show up as an arity error at `-o`, not as a wrong result.
- The diff is large (about 1450 lines added, 880 removed) because the world parameter was threaded by script. Two checks guard it: the output is byte-identical, and the mutants still bite. A reviewer may want to compare a sample of `G_K` defs against master's inline expressions.
- The shared projection inside the worlds is noted above. No check asserts that two projections are built.
