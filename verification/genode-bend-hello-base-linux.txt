  E1  musttail statement attribute (compiler, not libc)
      Error (genode-x86-gcc 14.2.0):
        hello.c:124:46: error: expected identifier or '(' before 'return'
          124 | #define WL_DYN(F)  __attribute__((musttail)) return wl_tab[F](WL_ALL)
        (also WL_JMP at hello.c:123, via WL_RETN at hello.c:1308 and others)
      What differs: the generated C is written for clang. It uses the
        statement attribute musttail (in GCC only from GCC 15), '#pragma clang
        fp contract(off)' (ignored by GCC with a warning), and preserve_none/
        preserve_most (guarded by __has_attribute). Genode 26.08 prescribes the
        25.05 tool chain, GCC 14.2.0. Removing musttail would change the
        evaluator's guaranteed tail calls, so it was not an option.
      Change: CUSTOM_CC = clang --target=x86_64-unknown-elf for this target
        only. Host clang 23.1.1 (Manjaro package clang 23.1.1-1), the compiler
        family the generated C targets. The bare-ELF target, like
        genode-x86-gcc, defines neither __linux__ nor __unix__, so the
        runtime's Linux-only blocks (sched_getaffinity, cgroup cpu.max reads,
        the Linux window fill) are compiled out exactly as with the Genode
        tool chain. Linking still uses genode-x86-g++ (prg.mk LD_CMD = $(CXX)).

  E2  MAP_NORESERVE (libc header)

  Analysis: main() parsed the RTS arguments (no 'unknown runtime option'
    message) and reached corpus_setup, which asks for a 1<<33 byte (8 GiB)
    term heap; the size is fixed in the generated C for --gpu off. Genode's
    libc mmap for MAP_ANON (repos/libports/src/lib/libc/file_operations.cc)
    rejects MAP_FIXED, ignores the address hint, allocates the whole length
    from its heap, and bzero()s it. The heap therefore requested 8 GiB plus
    16 KiB of RAM quota from init. init does not answer resource requests, so
    the libc blocks: the runtime's own "reservation failed" path (MAP_FAILED)
    is never taken and the component neither prints nor exits.

  Analysis: with enough quota the 8 GiB corpus mapping succeeds (corpus_map
    walks its hints from 1<<45 down; every libc result differs from the hint,
    so each is presumably unmapped and the final pool_mmap(size) is kept;
    the per-call sequence was not traced). On base-linux
    RAM dataspaces are files in /tmp/genode-<uid> (tmpfs), and the bzero
    touched them: host "shared" memory rose by about 10 GiB during the run
    and was released at exit; /tmp/genode-1000 was empty afterward.
    pool_stack() then maps 2 GiB + 16 KiB + 4*SIGSTKSZ for the evaluation
    stack and calls mprotect(p + 2 GiB, 16384, PROT_NONE) for the guard
    page. Genode's libc defines mprotect in dummies.cc as a weak DUMMY that
    logs "not implemented" and returns -1, so err_fail("stack guard
    failed") ends the component with exit value 1 before the first print.

BLOCKING ERROR
  Symbol: mprotect (called from pool_stack in hello.c, stack guard page).
  Genode 26.08 libc: weak dummy, returns -1 (repos/libports/src/lib/libc/dummies.cc:126).
  Why no build-configuration fix: the only flag-level route would be a
  -D macro that turns mprotect into a no-op returning 0. That removes the
  guard page between the evaluation stack and the alternate signal stack,
  i.e. it silently drops the runtime's stack-overflow fail-stop. It edits the
  evaluator's behavior by preprocessor instead of by text, so it is outside
  the task's rules, and it would hide exactly the fault row Task 3 must
  measure. Not done. (E2's MAP_NORESERVE=0 differs: it restores the meaning
  the flag has on the libc's own ABI and drops no check the runtime makes.)
  For Task 3: memory row: the 8 GiB reservation is committed and zeroed, not
  reserved (needs 8 GiB + 16 KiB quota; at 256M the libc blocks rather than
  failing); faults row: mprotect is missing, the guard page cannot be made,
  and startup stops there; event loop, threads, clock, process rows: not
  reached beyond main's argument parsing, sysconf(_SC_NPROCESSORS_ONLN)
  (cpu_count, called first in main), getenv("BENDRTS"), and _exit(1) from
  err_fail (the component exited with value 1; it did not hang).
